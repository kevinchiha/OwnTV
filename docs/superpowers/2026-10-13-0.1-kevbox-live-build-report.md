### Rolled-up minors

- task-11 — `kevbox:supabase/migrations/0008_watch_telemetry_reads.sql` (AC-43): The task's Verify recipe cannot pass as written, and the task did not cause this. On a fresh local stack, 0008 fails because public.watched_items is never created by any migration in 0000–0012. Separately, `eval "$(supabase status -o env)"` sets shell variables without exporting them, so the script (a child process) cannot see API_URL and the other values unless you run `set -a` first. The implementer was right to leave 0008 untouched. The plan's Verify line, or 0008 itself, needs fixing after the lanes merge. OUT OF REACH for this lane.
- task-11 — `kevbox:scripts/prove-member-playlist-rls.sh` (AC-44): AC-44 says a member cannot insert, update or delete. The proof checks only insert (POST). The migration revokes update and delete from authenticated, so the database already behaves correctly. A PATCH and a DELETE check with member A's token would cover the full criterion. Brief behaviour 3 asks only for POST, so this is extra coverage, not a missing requirement.
- task-11 — `kevbox:scripts/prove-member-playlist-rls.sh`: The local-only guard reads the host from the authority part of DB_URL. libpq also accepts host= and hostaddr= in the query string, so a URL like postgresql://127.0.0.1/postgres?host=remote would pass the guard and then connect elsewhere. The value normally comes from `supabase status`, so the risk is low. Refusing any DB_URL that contains host= or hostaddr= would close the gap.
- task-11 — `kevbox:lane-3-progress.md`: The commit adds lane-3-progress.md, which is not on the brief's Files list. It looks like the run's progress ledger rather than product code, but the owner should drop or move it when the lanes merge.
- task-12 — `src/app/live-actions.ts` (AC-49): editKevboxLive trims the typed password (and username) before saving, and sendToKevboxLive trims the sheet's Trex password. The brief only says an empty trimmed field is refused, not that values are stored trimmed. A Trex password with real leading or trailing spaces would be saved changed. Send and sheetDiffers are at least consistent with each other, so the TV and the 'differ' check agree.
- task-12 — `src/app/live-actions.ts` (AC-45): getKevboxLiveStatus('') returns serverSet: false and loginExists: false without reading anything, so the status can claim no server is set even when one is. The blocker list is correct (only no_client_number), and Task 13 should show the blocker text rather than trust serverSet in this case.
- task-12 — `src/app/live-actions.ts` (AC-52): saveTrexServerAddress compares the new address with the stored one outside the transaction, before changeTrexServer takes its 'for update' lock. If two saves run at once, both can go through and each writes an audit row. With one operator this is unlikely, and the row update stays correct because it filters on the value read under the lock.
- task-13 — `src/components/kevbox-live-section.tsx` (AC-45): With an empty client number the section shows "Not on KevBox Live" above the disabled Send and the no_client_number line. The brief's admin-5 note says the section shows only the disabled Send with that text. No wrong button appears, so the only cost is one extra line that could mislead, because without a client number there is no row to look up.
- task-13 — `src/components/kevbox-live-section.tsx`: load() after an action has no guard against a stale result. The mount effect cancels on a clientNumber change, but the post-action reload can still overwrite the status after the dialog switches to another customer. The window is small because the dialog usually remounts.
- task-13 — `src/components/kevbox-live-section.tsx`: formatSentAt formats in the browser's local time and returns 'NaN/NaN/NaN NaN:NaN' if sentAt cannot be parsed. Its date part reuses formatDate, which also uses local time, so this matches existing behaviour. A bad timestamp from the database would still show garbage instead of a blank.
- task-13 — `src/components/trex-server-card.tsx` (AC-52): Save is enabled before getTrexServerAddress resolves, so the admin can submit the empty initial value. saveTrexServerAddress rejects an empty or partial address, so nothing is written. The button could still wait for the load to finish.
