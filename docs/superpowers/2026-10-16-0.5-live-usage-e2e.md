### Notes

1. **The size check ran.** The first authorised call came at 18:10 Beirut, past 03:00, with
   `usage_size_checked_on` empty, so the size check ran on it and found the database under 4 GB
   (`"under"`, no message). Later calls answered `"skipped"`, as AC-20 says. The over-4 GB message
   is Task 7's tests; no Telegram variable was set anywhere in this run.
2. **Why the control.** A fleet of zeros alone would also pass if the fleet reads were broken. The
   one-off run with the TV's version set to 5.1.0.16 shows the same stretch counted once the TV is
   no longer a test TV, so the zeros come from the test-TV rule. `watched7`, `watched30` and
   `hours7` stay 0 in the control too: those periods end yesterday, and the only stretch is today's.
   For the same reason the member's own `last30Hours` is 0 while its week, month and top channel
   show the stretch.
3. **Same network cut as 0.4.** `svc wifi` does not cut this AVD (0.4 note 3), so the run used
   Android's per-app firewall from the start. I gave the network back while the app sat in the
   background and waited 20 s before bringing it forward; the row count was still 1 when `am
   start` ran. Rows 2 and 3 carry the same `received_at`, 15:14:38.037, and row 3 only ended at the
   second Home, so the queued stretch went out in the same call as row 3: the send on the second
   background. I did not read the table between `am start` and that Home.
