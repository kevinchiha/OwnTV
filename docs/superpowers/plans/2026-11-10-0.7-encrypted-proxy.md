# 0.7 Encrypted Proxy Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: `subagent-driven-development`. This plan
> states contracts, behaviour and constraints — **it deliberately contains no implementation or
> test bodies**. Read the file you are modifying before writing anything; the plan tells you what
> must be true, the codebase tells you how to say it.

**Goal:** A KevBox Live customer whose VPS proxy is on reaches persovps's Squid over TLS on `45.146.255.87:443`, so an inspecting internet company sees ordinary HTTPS to `northcache.uk`; the customer sees nothing new.
**Architecture:** On the TV, a small relay listens on `127.0.0.1:61129` and wraps each connection a player opens in TLS to persovps (by address, `northcache.uk` as the server name, Core's trust roots), so Core's one HTTP proxy setting, which ExoPlayer, mpv, the guide and the logos all follow, points at the relay. `ManagedProxy` decides relay or plain proxy from three new `member_playlist` columns and keeps the last encrypted address so the relay restarts at process start. kevbox.dev writes the columns from `VPS_PROXY_TLS_*` settings in every proxy write and in the 15-minute refresh, and marks encrypted TVs; persovps gets an `https_port` in the same Squid, written as files and a runbook that Kevin applies.
**Tech stack:** Kotlin, Koin, Core 1.0.69 (unforked; read-only source at `/home/kevin/projects/OwnTV/build/kevbox/core-1.0.69/OwnTV_Core-core-1.0.69/`), `javax.net.ssl`, OkHttp, JUnit 4; kevbox: Next.js 16, `pg`, Supabase (Postgres 17; disposable test container postgres:16), vitest, Node 24.22.1; persovps: Debian 13, Squid 6.13 (the GnuTLS build today; this phase moves it to Debian's `squid-openssl` build), nginx, certbot, fail2ban 1.1.0 (nftables ban action).

### Task 1: The relay: loopback listener, TLS to persovps, trust

The piece the players cannot do themselves: OkHttp and mpv only speak plain HTTP proxies, so the relay takes their plain connection on `127.0.0.1` and carries the same bytes inside TLS to persovps. It is pure networking with no wiring; Task 4 points Core's proxy at it. It never falls back: a failed check closes the player's connection, because a fallback would hand an inspecting internet company exactly what 0.7 hides.

**Delivers:** AC-14, AC-15, AC-16, AC-17 (the port rule), AC-22 (the debug-only extra roots the emulator check needs)

**Files:**

- Produces:

```kotlin
// kevbox/network/LocalRelay.kt
const val RELAY_PORT = 61129
const val RELAY_LOOPBACK = "127.0.0.1"

/** Where each connection goes: [addr] when it is a valid IPv4 address, else [host] through DNS. [host] is always the TLS server name and the name checked. */
data class RelayTarget(val host: String, val port: Int, val addr: String?)

interface Relay {
    /** Listens (binding once) and sends every new connection to [target]; open connections to a different target are closed. Returns the port. Throws IOException when no port can be bound. */
    fun start(target: RelayTarget): Int
    /** Closes the listener and every open connection. Safe when stopped. */
    fun stop()
}

class LocalRelay(
    trust: javax.net.ssl.X509TrustManager,
    lookup: (String) -> List<java.net.InetAddress>,
    preferredPort: Int = RELAY_PORT,
) : Relay

/** Pure. [text] as four bytes when it is a dotted-quad IPv4 address, else null. Never looks anything up. */
fun ipv4Bytes(text: String?): ByteArray?

// kevbox/network/RelayTrust.kt
/** The PEM a debug build reads from its external files folder for the emulator check. */
const val RELAY_TEST_CA_FILE = "kevbox-relay-test-ca.pem"
/** [base] alone unless [debug] is true and [extraPem] holds certificates; then [base] first, those roots after it. */
fun relayTrust(base: javax.net.ssl.X509TrustManager, debug: Boolean, extraPem: String?): javax.net.ssl.X509TrustManager
```

**Behaviour:**
1. `start(target)` when not listening binds a `ServerSocket` on `127.0.0.1` with `reuseAddress = true` (a restart must not lose the port to TIME_WAIT), trying in order: the port it last held in this process, `preferredPort`, then any free port (0). It returns the bound port. When already listening it keeps the port (AC-17); a target equal to the current one changes nothing; a different one becomes current and every open connection is closed, so nothing keeps flowing to the old address.
2. An accept loop on a daemon thread hands each accepted socket to a pool of daemon threads with no upper bound (a cached pool: every accepted connection gets its threads at once, never waits in a queue). Each connection holds its threads for its whole life, and Core sends everything through the one proxy setting: the stream, the guide, logos fetched several at a time, and OkHttp's idle keep-alive connections, so a capped pool would silently stop new connections, the channel's included. Per connection: the remote address is `InetAddress.getByAddress(target.host, ipv4Bytes(target.addr))` when the bytes are non-null (no DNS lookup), else `lookup(target.host)` tried in order until one connects; TCP connect within 10 s; TLS handshake within 15 s with `target.host` as the server name (set explicitly in `SSLParameters.serverNames`, not left to the socket factory); the chain checked by `trust`; then the host name checked explicitly against the session (OkHttp's `OkHostnameVerifier`, the verifier every Core request already uses). After the handshake the read timeout is cleared.
3. Then bytes are copied both ways unchanged until either direction ends (EOF or error); that closes both sockets (AC-15). The relay never parses, adds or removes a byte: the proxy request and its `Proxy-Authorization` header travel inside the TLS as the player wrote them.
4. Any failure before the copy starts (lookup, connect, handshake, trust, host name) closes the player's socket and nothing else: no second target, no plain port, no direct connection (AC-16).
5. `stop()` closes the listener and every open connection; the accept thread ends; the port stays remembered for the next `start` in this process. `start`, `stop` and the connection list share one lock.
6. `ipv4Bytes`: exactly four parts separated by dots, each 1 to 3 digits, value 0-255, no leading zero except `0` itself, nothing else (no spaces, signs, hex or trailing dot). Anything else, null or blank is null.
7. `relayTrust`: `debug` false, or no certificate in `extraPem`, returns `base` itself. Otherwise a trust manager that accepts what `base` accepts and, when `base` refuses, accepts a chain ending at one of the extra roots; its accepted issuers are both sets.
8. `make-test-certs.sh` writes, with `openssl` and `keytool`, valid for 36,500 days: a test root CA (PEM) and an intermediate CA signed by it, as Let's Encrypt chains are; a server key and certificate for `relay-test.invalid` signed by the intermediate, one for `wrong.invalid` signed by the intermediate, and one for `relay-test.invalid` signed by a second CA (its PEM written too) that the base trust in the tests never includes. Each server one is PKCS#12 with password `test` (not a secret) and carries its leaf plus any intermediate, so the fixture server sends the whole chain and the relay trusts the root alone. Its header says the files are test-only and how to regenerate them.

**Constraints:**
- Loopback only (AC-14): the bind address is the literal `127.0.0.1`, never the wildcard. Another app on the same TV can reach it, and gains nothing: the relay adds no credentials.
- A trust manager on its own does not check host names on Android, which is why item 2 checks the name explicitly. If `OkHostnameVerifier` is not reachable in the OkHttp version on the classpath, write a minimal subject-alternative-name check (exact name, or a single-label `*.` wildcard) and say so in the commit body.
- Pins in `CoreContractTest` for what Task 4 reads: `tv.own.owntv.core.network.ExtraTrustAnchors(InputStream)` and its `trustManager`, the resource id `tv.own.owntv.core.R.raw.isrg_extra_roots`, and `tv.own.owntv.core.network.DnsConfigHolder.dns`.
- No log line carries the target host, address, port or any byte; class names only.
- Tests never bind the real 61129 except one assertion that `RELAY_PORT` is 61129: they pass a free port as `preferredPort`, so a parallel run cannot collide.

**Test intents:**
- `carries bytes both ways to the address, with the name as SNI and no lookup` — fixture server for `relay-test.invalid` on 127.0.0.1, target addr `127.0.0.1`, a `lookup` that fails the test if called; the server sees requested name `relay-test.invalid`; all 256 byte values and CRLFs round-trip unchanged; with 32 connections held open at once, a 33rd still round-trips (no capped pool); then the server closes and the player reads EOF (AC-15).
- `a wrong name or an untrusted chain closes the player and tries nothing else` — the `wrong.invalid` server and the second-CA server: the player reads EOF, a decoy plain listener on another loopback port receives no connection, `lookup` is never called (AC-16).
- `no address or a bad one looks the name up` — addr null, `999.1.1.1`, `045.1.1.1`, `1.2.3`, `1.2.3.4.`: `lookup("relay-test.invalid")` is called and the copy works; `ipv4Bytes` gives four bytes for `45.146.255.87` and null for each bad form (AC-15).
- `listens on loopback, falls back from a busy port, and keeps its port` — preferred port free: bound there, local address loopback; preferred port held by another socket: a different port; `start` with a new target returns the same port; `stop` then `start` returns it again (AC-14, AC-17).
- `extra roots count only in a debug build` — the second CA as `extraPem`: with `debug` false its server is refused; with `debug` true it is accepted; `base`-trusted chains pass both ways.
