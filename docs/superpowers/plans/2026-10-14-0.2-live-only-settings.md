# 0.2 Live-only settings Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: `subagent-driven-development`. This plan
> states contracts, behaviour and constraints — **it deliberately contains no implementation or
> test bodies**. Read the file you are modifying before writing anything; the plan tells you what
> must be true, the codebase tells you how to say it.

**Goal:** Settings and More in KevBox Live show only what works in a live-TV-only app; the preview box always plays with sound; nothing can break the grow, schedule a recording or start Multiview.
**Architecture:** One fork-only list, `kevbox/settings/LiveOnlySettings.kt`, names the hidden row keys and the fixed values. Upstream files gain small `// KevBox:` filter hooks that read it: one hook in the Video player row composable (`Row2`), one filter on the Settings root list and search, one map on the Quick pins, constant reads in the view models. Fixed values are read, never written to storage, so Kevin's TV follows them at once. Every new or renamed user-facing string is a new `kevbox_*` key in English and French, so other languages fall back to English.
**Tech stack:** Kotlin, Jetpack Compose for TV, Koin, Core 1.0.67 (unforked, read-only at `build/kevbox/core-1.0.67/OwnTV_Core-core-1.0.67/`), JUnit 4, Gradle (AGP 9).
**Spec:** `docs/superpowers/specs/2026-10-14-0.2-live-only-settings-design.md`. Cite its criteria as `AC-n`.

## Global constraints

- Repo `/home/kevin/projects/OwnTV`. Paths below without a prefix are under `app/src/main/java/tv/own/owntv/`; test paths are under `app/src/test/java/tv/own/owntv/`.
- Run Gradle as `GRADLE_USER_HOME=/home/kevin/.gradle ./gradlew ...`. The repo's `.envrc` points `GRADLE_USER_HOME` at an empty per-folder cache, which in a worktree means a full download.
- Full gate (the reviewer's check): `GRADLE_USER_HOME=/home/kevin/.gradle ./gradlew testStandardDebugUnitTest lintStandardDebug assembleStandardRelease`. All three task names exist (checked 2026-10-14). The unit-test count may only grow.
- Core is not forked. `gradle/libs.versions.toml` stays unchanged; every change lives in the app module.
- Every changed line of an upstream file carries a `// KevBox:` comment within 3 lines that says what changed and why (`<!-- KevBox: -->` in XML). A deleted block leaves its `// KevBox:` comment where it was. `tools/kevbox/check-divergence.sh` enforces the 3-line rule.
- UPSTREAM-SYNC.md is written by Task 12 alone, after all lanes merge: one row per changed upstream file with a grep proof. Other tasks do not edit it.
- No deletion of upstream Multiview, recording, VOD, Home, metadata or OpenSubtitles code. Make it unreachable (a condition, a filter, a constant) and leave the code in place, so upstream merges stay clean.
- New fork-only Kotlin lives under `kevbox/` (tests under `kevbox/` in the test tree) and starts with the line `// KevBox Live fork only: this file does not exist upstream (ahXN00/OwnTV).`
- User-facing text: English in `app/src/main/res/values/kevbox_strings.xml`, French in the new `app/src/main/res/values-fr/kevbox_strings.xml`. Other languages fall back to English. Never override a Core string key by name for a rename: Core ships 26 locales, so an override in two of them leaves the other 24 on the old wording. Use the new `kevbox_*` keys from Task 1 and point the code at them. Never hand-edit the generated `kevbox_brand_strings.xml`.
- Only Task 1 writes `kevbox_strings.xml`, `values-fr/kevbox_strings.xml` and `tools/i18n/safe_literals.txt`. The build fails on any Kotlin string literal not classified in `safe_literals.txt`, which keeps a count per file and literal. So every other task adds no Kotlin string literal and deletes no line holding one: use the constants and string resources Task 1 declares, write `String()` where an empty string is needed, and hide upstream code with a condition rather than deleting it. A task that finds it cannot keep this rule stops and reports; it does not edit `safe_literals.txt`.
- `SettingsScreen` is one composable at the JVM's 64 KB method limit. Add as little as possible inside its body; put new row builders, search entries that need no inline state, and counting logic in functions outside it. A "Method too large" compile error means more must move out of line.
- No test reads a source file as text to check what it contains (an import, a prop, a string); test behaviour through the code's own outputs. The existing upstream tests that scan source (`SettingsSearchCoverageTest`, `VideoQuickRowCatalogueTest`, `SettingsSearchRowsTest`) stay green; adapt them minimally under `// KevBox:` comments, add no new source-scanning tests.
- Tests are plain JUnit 4 (`org.junit.Assert`), with `runBlocking` and hand-written fakes where needed. There is no Robolectric, mockk, Compose test rule or coroutines-test, so only pure functions are unit-tested.
- Read every file on a task's **Design skills** line before writing any code for it.
- UI follows the project's own design system: Stage tokens and components in `ui/stage` and `ui/theme/StageTokens.kt`. No new look. No task takes screenshots.
- Gated, never run by a lane task: `git push` (and never without `git fetch` first, never forced); `./release.sh` and `gh release create`; any deploy or write on persovps; anything against the production KevBox Supabase; printing or committing anything from `~/secrets/kevbox-keys/*`, `local.properties` or keystores. Installing on Kevin's TV over adb happens only in Task 13. Never restart the dsh server on port 3080.
- Commit messages are plain and imperative, with no AI attribution and no `Co-Authored-By` trailer.

### Task 2: Fixed values in the shell and settings view models

The accent, focus outline, Quick pins and Live preview switch read Task 1's values instead of storage. Core itself refuses to save Live preview "on" while the Live panel width is 0 (Core `SettingsRepository.kt:2387-2391`), so skipping the app's dialog alone would leave the switch dead.

**Delivers:** AC-9, AC-14, AC-16

**Files:**
- Modify: `features/shell/ShellViewModel.kt`
- Modify: `features/settings/SettingsViewModel.kt`

**Design skills:** `~/.agents/skills/ui-ux-pro-max/SKILL.md`

**Interfaces:**
- Consumes: `LiveOnlySettings.ACCENT_HEX`, `FOCUS_HIGHLIGHT_HEX`, `quickPins` (Task 1).
- Produces: `SettingsViewModel.quickPinnedKeys` already filtered (Tasks 4 and 10 read it); `SettingsViewModel.livePreviewPanelActive` always true.

**Behaviour:**
1. `ShellViewModel.customAccent` emits `LiveOnlySettings.ACCENT_HEX` and `focusHighlight` emits `LiveOnlySettings.FOCUS_HIGHLIGHT_HEX`, whatever storage holds. `MainActivity` feeds both to the theme, so every screen and focus ring turns #6FB0FF (AC-14). `focusHighlightWidth` still reads storage.
2. `SettingsViewModel.quickPinnedKeys` is the stored list passed through `LiveOnlySettings.quickPins`. On Kevin's TV, whose pins are Core's six, Quick shows Live preview, Channel numbers, Check for update (AC-9).
3. `SettingsViewModel.livePreviewPanelActive` is always true, so neither toggle opens `LivePreviewPanelHiddenDialog` (AC-16). This covers the root toggle, the Video player row and its Quick binding at once.
4. `SettingsViewModel.setLivePreviewEnabled(true)` first turns the Live panel-width override off with Core's `setPanelWidths(PanelSection.LIVE, enabled = false, shares)`, passing the stored shares from `panelShares(PanelSection.LIVE).first()` so they survive; it skips that write when the override is already off. Then it saves Live preview on. Read Core's `livePreviewPanelHidden` (Core `SettingsRepository.kt:2054-2058`) for the exact condition Core checks. `setLivePreviewEnabled(false)` is unchanged.

**Constraints:**
- No storage write for the accent or focus colour: the spec's decision is that fixed values are read, so Kevin's TV follows them without a migration.

#!/usr/bin/env bash

# Builds the current tree as a signed release with the version Kevin's TV already runs and installs
# it over adb, keeping the app's data. Usage: tools/kevbox/tv-install.sh [A.B.C.K]

apk=app/build/outputs/apk/standard/release/app-standard-release.apk
die() { echo "tv-install: $*" >&2; exit 1; }

echo "tv-install: building KevBox Live $version (code $code)"
(
  # shellcheck source=/dev/null
  source "$signing_env"
  # shellcheck source=/dev/null
  source "$supabase_env"
  export KEYSTORE_FILE="$NUVIO_RELEASE_STORE_FILE"
