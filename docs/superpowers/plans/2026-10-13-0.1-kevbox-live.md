# KevBox Live 0.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: `subagent-driven-development`. This plan
> states contracts, behaviour and constraints — **it deliberately contains no implementation or
> test bodies**. Read the file you are modifying before writing anything; the plan tells you what
> must be true, the codebase tells you how to say it.

**Goal:** the admin sets, changes or removes a member's Xtream playlist on kevbox.dev, and the
member's TV, running the rebranded OwnTV fork "KevBox Live", picks it up by itself within 15
minutes.
**Architecture:** the TV signs in to the hosted KevBox Supabase with plain OkHttp REST calls
(GoTrue sign-in and refresh, a PostgREST read of `member_playlist`, the `get_access_verdict` RPC)
and turns the rows into one local Xtream source through Core's own repository and DAO classes,
keeping its client-number mapping in app-owned storage. All fork code sits in the app layer under
`tv/own/owntv/kevbox/`; upstream files change only where a screen must be hidden or a hook added,
each change marked `KevBox:`. kevbox.dev gains migration 0013, server actions in their own file,
a KevBox Live section in the customer window and a Trex server card on Settings.
**Tech stack:** Kotlin, Jetpack Compose for TV, Koin, Room (Core's), OkHttp 5, org.json, Android
Keystore, Gradle (AGP 9); Next.js 16, React, shadcn, vitest, node-postgres, Supabase (Postgres 17).
**Spec:** `docs/superpowers/specs/2026-10-13-0.1-kevbox-live-design.md` (in the OwnTV repo).
Cite its criteria as `AC-n`.
**Length:** about 1,440 lines for 14 tasks, past the usual ~1,300. The spec keeps all 55 criteria in
one phase (its Size decision), and the long tasks are long because of verbatim deliverables and
cross-task contracts: the migration DDL (Task 11), the member strings (Task 7), the Supabase and
reconcile declarations (Tasks 4, 5) and the server-action signatures and admin copy (Task 12).

```kotlin
object KevBoxVersion {
    data class Parts(val a: Int, val b: Int, val c: Int, val k: Int)
    fun parse(name: String): Parts?      // null unless exactly A.B.C.K with A,B,C in 0..99, K in 1..99
    fun code(name: String): Int?         // A*1000000 + B*10000 + C*100 + K, null when parse fails
}
```

```sh
tools/kevbox/version.sh code <A.B.C.K>   # prints the version code; exit 2 with a message on stderr if invalid
tools/kevbox/version.sh base <A.B.C.K>   # prints A.B.C; exit 2 if invalid
```

The `defaultConfig` lines land exactly as below (keep upstream's comments above them, add these):

```kotlin
        // KevBox: own application ID, so KevBox Live installs beside stock OwnTV (tv.own.owntv) and KevBox TV (tv.kevbox).
        applicationId = "tv.kevbox.live"
        // KevBox: four-number versions A.B.C.K (upstream A.B.C + KevBox K); code A*1000000+B*10000+C*100+K,
        // computed by tools/kevbox/version.sh. The fallback 99.99.99.99 = 99999999 keeps a local build above every release.
        versionCode = (System.getenv("VERSION_CODE") ?: "99999999").toInt()
        versionName = System.getenv("VERSION_NAME") ?: "99.99.99.99"

        // KevBox: the KevBox Supabase project the TV signs in to. Env var (release.sh) > Gradle property
        // (-Pkevbox.supabaseUrl / -Pkevbox.supabaseAnonKey, e.g. a local stack for the emulator) > blank.
        val kevboxSupabaseUrl = System.getenv("KEVBOX_SUPABASE_URL")
            ?: providers.gradleProperty("kevbox.supabaseUrl").orNull ?: ""
        val kevboxSupabaseAnonKey = System.getenv("KEVBOX_SUPABASE_ANON_KEY")
            ?: providers.gradleProperty("kevbox.supabaseAnonKey").orNull ?: ""
        buildConfigField("String", "KEVBOX_SUPABASE_URL", "\"$kevboxSupabaseUrl\"")
        buildConfigField("String", "KEVBOX_SUPABASE_ANON_KEY", "\"$kevboxSupabaseAnonKey\"")
```

**Behaviour:**
1. `parse` accepts only four dot-separated decimal numbers with no sign, prefix or suffix:
   `5.1.0.1` parses; `v5.1.0.1`, `5.1.0`, `5.1.0.0`, `5.100.0.1`, `5.1.0.1-beta` do not.
2. `code("5.1.0.1") == 5010001`, `code("5.1.0.2") == 5010002`, `code("5.2.0.1") == 5020001`,
   `code("99.99.99.99") == 99999999` (the local fallback is the formula's ceiling).
3. `version.sh` applies the same rules and arithmetic in plain bash (no Python, no Gradle), so
   `release.sh` can call it before any build.
4. `namespace` stays `tv.own.owntv`: only the application ID changes, so the R class and every
   upstream package name stay put.

**Constraints:**
- `minSdk = 26` stays (spec Decision: OwnTV's Android 8 minimum stays).
- Every provider authority in the merged manifest must follow the new ID. Upstream's
  FileProvider and startup provider use `${applicationId}`; check Core's merged-in providers
  too. A hard-coded `tv.own.owntv.` authority or a fixed custom permission name would block
  installing next to stock OwnTV (AC-1).
- Leave the `owntv://` deep-link scheme alone: Core builds those URIs for the TV home rows, and
  Core stays unforked.
- Do not touch the signing block: it already reads `KEYSTORE_FILE`, `KEYSTORE_PASSWORD`,
  `KEY_ALIAS` and `KEY_PASSWORD` from the environment, which is how `release.sh` (Task 10) signs.

**Test intents:**
- `code follows A*1000000 + B*10000 + C*100 + K` — the four spec examples above.
- `parse rejects K of 0, a segment over 99, three numbers, a v prefix and a suffix`
- `version.sh agrees with KevBoxVersion` — runs `bash ../tools/kevbox/version.sh code <v>` through
  `ProcessBuilder` (the unit-test working directory is `app/`) for valid and invalid inputs and
  compares output and exit code with `KevBoxVersion.code`.

**Verify:** in `OwnTV:` run
`./gradlew testStandardDebugUnitTest --tests 'tv.own.owntv.kevbox.release.*' && find app/build/intermediates -path '*standardDebug*' -name AndroidManifest.xml -path '*merged*' | xargs grep -ho 'android:authorities="[^"]*"' | sort -u`
Expected: tests pass; every authority printed starts with `tv.kevbox.live`.

   override in the matching app folder, with every `OwnTV` replaced by `KevBox Live`. Attributes
   (`translatable`, `formatted`), placeholders, escapes, every plural quantity and every array item
   carry over unchanged.
3. Output is deterministic (sorted by name) and starts with

4. `check-brand.sh` runs the newest `$ANDROID_HOME/build-tools/*/aapt2` (default

   plural and array value containing `OwnTV` in every configuration, drops names listed in the
   allowlist, prints each remaining hit as `name [config]: value` and exits 1 if any remain. It
   checks values, never resource names (`owntv_icon_*` is a name, not text).
5. `brand-allowlist.txt` holds one name per line with a `#` reason, and only licence or
   attribution text that credits the upstream project. Start with `settings_about_license`
   ("© 2026 OwnTV · GPLv3 License"); add any other credit line only with its reason.

**Constraints:**
- Never hand-edit a generated override (spec Decision: a script reruns cleanly at every Core bump).
- App resources override library resources of the same name and type; a plural must be overridden
  whole or AAPT merges a broken set.
- Strings with a GitHub URL containing `OwnTV` still get replaced: the screens that show them are
  hidden (Task 9), and AC-3 counts every shipped string.
- No Kotlin in this task: only the `owntv-app` lane touches Kotlin and `safe_literals.txt`.

**Test intents:** none in Gradle. `--check` proves the generated files match Core, and
`check-brand.sh` on a real release APK is the AC-3 test.

**Verify:** in `OwnTV:` run

```kotlin
// KevBoxModels.kt
data class PlaylistRow(val clientNumber: String, val name: String, val serverUrl: String,
                       val username: String, val password: String)
enum class AccessVerdict { ALLOWED, NO_ROW, LOCKED }
sealed interface SignInResult {
    data class Success(val email: String) : SignInResult
    data object WrongCredentials : SignInResult
    data object NoNetwork : SignInResult
    data object Failed : SignInResult
}
sealed interface Fetch<out T> {
    data class Ok<T>(val value: T) : Fetch<T>
    data object Failed : Fetch<Nothing>          // network, timeout, 5xx, malformed, RPC error
    data object SessionRejected : Fetch<Nothing> // the server refused the refresh token
    data object SignedOut : Fetch<Nothing>       // no stored session
}

// SupabaseApi.kt
sealed interface ApiResponse { data class Http(val code: Int, val body: String) : ApiResponse; data object NoNetwork : ApiResponse }
class SupabaseApi(http: OkHttpClient, baseUrl: String, anonKey: String) {
    suspend fun passwordGrant(email: String, password: String): ApiResponse
    suspend fun refreshGrant(refreshToken: String): ApiResponse
    suspend fun selectPlaylists(accessToken: String): ApiResponse
    suspend fun accessVerdict(accessToken: String): ApiResponse
    suspend fun logout(accessToken: String): ApiResponse
}

// SessionStore.kt / KeystoreTokenCipher.kt
data class StoredSession(val userId: String, val email: String, val accessToken: String,
                         val refreshToken: String, val expiresAtMs: Long)
interface TokenCipher { fun encrypt(plain: ByteArray): ByteArray; fun decrypt(sealed: ByteArray): ByteArray? }
interface SessionStore { fun load(): StoredSession?; fun save(session: StoredSession); fun clear() }
class PrefsSessionStore(prefs: SharedPreferences, cipher: TokenCipher) : SessionStore
class KeystoreTokenCipher : TokenCipher   // AES-256-GCM, AndroidKeyStore alias "kevbox_live_session"

// KevBoxAuth.kt
class KevBoxAuth(api: SupabaseApi, store: SessionStore, now: () -> Long) {
    val email: StateFlow<String?>                    // null = signed out
    suspend fun signIn(email: String, password: String): SignInResult
    suspend fun playlists(): Fetch<List<PlaylistRow>>
    suspend fun verdict(): Fetch<AccessVerdict>
    suspend fun signOut()                            // best-effort server logout, then clear the store
}
```

The requests, exactly (every one sends `apikey: <anon key>`; the last three also send
`Authorization: Bearer <access token>`; bodies are `Content-Type: application/json`):

```
POST {url}/auth/v1/token?grant_type=password        {"email": "...", "password": "..."}
POST {url}/auth/v1/token?grant_type=refresh_token   {"refresh_token": "..."}
GET  {url}/rest/v1/member_playlist?select=client_number,name,server_url,username,password&order=name.asc
POST {url}/rest/v1/rpc/get_access_verdict           {}
POST {url}/auth/v1/logout
```

**Behaviour:**
1. `signIn`: 200 → read `access_token`, `refresh_token`, `expires_in` (seconds), `user.id`,
   `user.email`; save; `email` emits; `Success`. 400 whose JSON `error` is `invalid_grant` or
   whose `error_code` is `invalid_credentials` → `WrongCredentials`, nothing saved. Connection
   failure, unknown host or timeout → `NoNetwork`. Anything else, or a blank `KEVBOX_SUPABASE_URL`
   (checked before any call) → `Failed`.
2. Before `playlists`, `verdict` or `signOut`, refresh when the access token expires within 60 s.
   A 401 from PostgREST triggers one refresh and one retry.
3. Refresh 200 → save the new pair (refresh tokens rotate: always keep the newest). Refresh 400 or
   401 → `SessionRejected`, and the store is left for Task 8's sign-out path to clear in one place.
   Refresh `NoNetwork` or 5xx → `Failed`, session kept.
4. `playlists`: 200 with a JSON array whose every element has the five string fields →
   `Ok(rows)`; anything else → `Failed`. `verdict`: 200 with the JSON string `"ALLOWED"`,
   `"NO_ROW"` or `"LOCKED"` → `Ok`; anything else, including the function's "not authenticated"
   error → `Failed`.
5. `PrefsSessionStore` writes one encrypted blob (all five fields as JSON) to SharedPreferences
   file `kevbox_live_session`. A blob that no longer decrypts (key lost) loads as `null`: the TV
   shows sign-in rather than crashing.
6. `KevBoxAuth` built over a store that already holds a session starts signed in, with no call
   made (AC-12: restart and reboot need no password).

**Constraints:**
- JSON with `org.json` (built into Android); OkHttp calls on `Dispatchers.IO`, 15 s timeouts, from
  a client derived from the app's Koin `OkHttpClient` with `newBuilder()` (Task 8 wires it).
- Never log a token, password, email or response body.
- `signOut` ignores the logout call's outcome: sign-out must work offline.
- `allowBackup="false"` is already set upstream, so the encrypted blob never leaves the device.
