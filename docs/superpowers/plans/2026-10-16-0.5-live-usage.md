# 0.5 Live usage Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: `subagent-driven-development`. This plan
> states contracts, behaviour and constraints — **it deliberately contains no implementation or
> test bodies**. Read the file you are modifying before writing anything; the plan tells you what
> must be true, the codebase tells you how to say it.

**Goal:** On kevbox.dev Kevin sees, per KevBox Live customer and across all of them, how often they watch, their honest hours, and which channels, categories and programmes they watch, up to 13 months back, plus a list of paying customers who are drifting away or have gone quiet.
**Architecture:** The TV cuts live play into stretches (0.4's play test and scene), keeps them in a saved queue and sends them in batches to a new Supabase function `record_live_stretches`, which shifts them by the TV's clock error. kevbox gets migration `0017_live_usage.sql` (raw stretches, day rows, the counting rule in SQL), an hourly roll-up route with a daily size check, usage reads in `@kevbox-admin/core`, a tabbed customer window with a Usage tab, and a KevBox Live page that replaces Live errors.
**Tech stack:** Kotlin, Koin, Core 1.0.67 (unforked; read-only source at `/home/kevin/projects/OwnTV/build/kevbox/core-1.0.67/OwnTV_Core-core-1.0.67/`), JUnit 4; kevbox: Next.js 16, `pg`, Supabase (Postgres 17; the disposable test container is postgres:16), vitest, Node 25.9.0, recharts, shadcn components in `kevbox:src/components/ui/`.
**Spec:** `docs/superpowers/specs/2026-10-16-0.5-live-usage-design.md`. Cite its criteria as `AC-n`.
**Size:** 13 tasks, past the usual 12 because the kevbox web side needs one shared step (Task 6) before three lanes can run side by side. Spec `Size:` keeps the phase whole at 43 criteria.

**Behaviour:**
1. `recordLiveStretches` posts to `rest/v1/rpc/record_live_stretches` with exactly the four keys `p_device_id`, `p_app_version`, `p_tv_now`, `p_entries`, over the existing direct client, never logged.
2. `toEntry` writes exactly the ten entry keys of the Global constraints; a null field goes out as JSON null.
3. `DiaryQueue` keeps finished stretches, oldest first, in `file` (whole-file rewrite through a temp file and a rename, as `ErrorQueue` does); a missing or unreadable file starts empty. Past `DIARY_QUEUE_MAX` the oldest go first (AC-8). Each entry carries the member id it was added for; the tag stays on the TV.
4. The open stretch lives in `openFile`, a separate small file: Task 2 rewrites it every 60 s, and rewriting a 2,000-entry queue that often would wear the TV's flash. `recoverOpen()` moves a saved open stretch into the queue, with its saved `endedAtMs`, and clears the file; at or above 10 s only (AC-6).
5. `dropNotRecordedBy(userId)` removes every stretch tagged with another member, open file included (AC-8). Unlike `ErrorQueue`, nothing is ever untagged: a signed-out TV adds nothing, so there is nothing to adopt.
6. `sendOnce()`: signed out, nothing. Otherwise drop other members' stretches, take up to 200 of this member's, send them with `tvNow = playedAtText(now(), zone())`. A 2xx answer removes exactly the ids sent; no network, `Fetch.Failed`, `SignedOut`, `SessionRejected`, a thrown exception, status 0 or any non-2xx keeps them all (AC-7). `sendOnce()` makes exactly one call. The trigger (the tick or `sendNow()`) calls it again at once after a 2xx while this member's stretches remain, at most 10 calls per trigger.
7. `start()` sends on a 15-minute tick, and calls `dropNotRecordedBy` whenever `auth.userId` turns to a member; `sendNow()` sends once. A single mutex makes overlapping triggers wait, so a batch never goes out twice.

**Constraints:**
- Files: `kevbox_live_diary.json` and `kevbox_live_diary_open.json` in `noBackupFilesDir`, like the error queue: this TV's alone, never in a backup.
- Every launch body is guarded like `PlayNotes.guarded` (rethrow cancellation, log the class name only): the app scope has no handler, and a crash here would stop playback (0.4 finding O2).
- No retry tighter than the tick. A 404 (function not on the server yet) or a 401 keeps the batch like any other failure.

**Test intents:**

- `a 2xx removes exactly the sent stretches; a failure keeps them` — 250 queued: the first call carries 200, a 200 answer leaves 50; no network, 500 and a throw each leave all 250 (AC-7).

**Behaviour:**
1. A stretch opens when the look passes 0.4's play test (`playLookOf`: live, not catch-up, picture showing, no failure) and closes on: a channel change, a failure, catch-up, the app going to the background, a box/full-screen switch, the programme's `stopMs` passing, or a title appearing for a stretch that opened blank. Where play goes on, the next stretch opens at that same moment with the new title (AC-2).
2. A stop: when the look stops playing, the stretch is held as stalled from that moment. Playing again within `STALL_GRACE_MS` on the same channel and surface continues it; otherwise it closes with `endedAtMs` at the stall's start. A failure (`failed`, from either engine's `errorInfo`) or catch-up (`catchup`) is not a stall: it closes at once, with no grace. The watcher maps 0.4's `PlayView.failed` and `PlayView.catchup` into these two fields and never folds them into `playing`.
3. Under `STRETCH_MIN_MS` → never queued (AC-3). Catch-up, films, Multiview tiles and the Home hero never open one: they fail the play test or never reach these engines (AC-3).
4. At open: programme = `GuideNow.nowOn(scene.channelEntity)?.title`, blank → null (AC-4); `providerHost = Scrubber.host(streamUrl)`; `proxy = ProxyInUse.current()` (false when it throws). While a stretch is open with a null programme, `GuideNow` is asked again every 60 s.
5. At close: `lastPressAtMs` is the latest press at or before the stretch's `endedAtMs` (AC-5): a stall close uses the `lastPressMs` the cutter saw when the stall began, never a press made during the grace. The finished stretch goes to `DiaryQueue.add` with the signed-in member; signed out, it is dropped (AC-8).
6. Every `OPEN_SAVE_MS` the open stretch, closed as of now, goes to `DiaryQueue.saveOpen`; a normal close calls `clearOpen` (AC-6).
