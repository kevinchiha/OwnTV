# 0.3 Error reporting Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: `subagent-driven-development`. This plan
> states contracts, behaviour and constraints — **it deliberately contains no implementation or
> test bodies**. Read the file you are modifying before writing anything; the plan tells you what
> must be true, the codebase tells you how to say it.

**Goal:** KevBox Live sends crashes and freezes to its own Sentry project and every playback, playlist and guide failure (with the raw status TiviMate would show) to a new `live_error` table, plus a usage check-in to `live_device`; kevbox.dev shows both in the customer window and on a new "Live errors" page.
**Architecture:** A fork-only reporter in `app/src/main/java/tv/own/owntv/kevbox/errors/` watches Core's public failure feeds (`LivePreviewEngine.errorInfo`, `OwnTVPlayer.errorInfo`, the catalog sync result, `EpgSource.lastError`), maps each failure to a code, runs an Xtream account check when the status hides the reason, dedupes, queues on disk and sends batches to the Supabase function `record_live_errors`. Sentry (crashes, ANRs, native crashes only) starts by hand in `OwnTVApp` right after Core's `CrashRecorder`. kevbox gets migration `0015_live_error.sql`, read functions in `@kevbox-admin/core`, four admin routes and two UI additions; one code list, kept as a byte-identical JSON file in both repos, ties the app's codes to kevbox's labels.
**Tech stack:** Kotlin, Koin, Core 1.0.67 (unforked; read-only source at `/home/kevin/projects/OwnTV/build/kevbox/core-1.0.67/OwnTV_Core-core-1.0.67/`), Sentry Android SDK 8.60.0 + Sentry Android Gradle plugin 6.23.0, JUnit 4; kevbox: Next.js 16, `pg`, Supabase (Postgres 17 per `kevbox:supabase/config.toml`; the disposable test container is postgres:16), vitest, shadcn components in `kevbox:src/components/ui/`.
**Spec:** `docs/superpowers/specs/2026-10-14-0.3-error-reporting-design.md` (research it relies on: `docs/superpowers/2026-10-14-0.3-error-reporting-tivimate-codes.md`). Cite its criteria as `AC-n`.
**Size:** 13 tasks in three lanes. Lane `app` (OwnTV): Tasks 1–6, then 13. Lane `db` (kevbox): Tasks 7, 8. Lane `web` (kevbox): Tasks 9–12.

```kotlin
// KevBox Live fork only: this file does not exist upstream (ahXN00/OwnTV).
package tv.own.owntv.kevbox.errors

object LiveErrorCodes {
    // One const per fixed code, upper snake case: NET_TIMEOUT = "net_timeout", ACCOUNT_WRONG_LOGIN = "account_wrong_login", ...
    val FIXED: Set<String>                       // exactly the JSON "fixed" list
    fun http(status: Int): String                // "http_403"
    fun isKnown(code: String): Boolean           // in FIXED, or matches ^http_[1-9][0-9]{2}$
}

enum class Engine(val wire: String) { EXO("exo"), MPV("mpv") }

data class Classified(val code: String, val httpStatus: Int?, val errorName: String?)

data class AccountResult(val status: String, val activeCons: Int?, val maxConnections: Int?)

object AccountStatus {
    const val ACTIVE = "active"; const val EXPIRED = "expired"; const val BANNED = "banned"
    const val DISABLED = "disabled"; const val WRONG_LOGIN = "wrong_login"; const val UNREACHABLE = "unreachable"
}

object ErrorClassifier {
    fun playback(engine: Engine, raw: String?, reason: PlayerFailureReason?, online: Boolean): Classified
    fun playlist(message: String?, online: Boolean): Classified
    fun guide(message: String?, online: Boolean): Classified
    /** Applies an account check result (AC-13); [playlist] enables playlist_max_connections. */
    fun withAccount(c: Classified, account: AccountResult?, playlist: Boolean): Classified
}

object Scrubber {
    const val MESSAGE_MAX = 160
    /** Null in, null out. [max] cuts the result after scrubbing; null keeps the full length. */
    fun text(input: String?, secrets: Collection<String>, max: Int? = null): String?
    /** The host of an address, lowercased, or null; never a path, port, query or credential. */
    fun host(address: String?): String?
}
```

**Behaviour:**
1. `playback`: the status is `PlayerErrors.httpStatusIn(raw)` when it lies in 100..999; then the code is `http_<n>` and `httpStatus` is n, standard or not (403, 458, 884). The status wins over every rule below.
2. `errorName`: when `raw` starts with a Media3 constant name (`ERROR_CODE_` followed by `[A-Z0-9_]+`), that name; on `Engine.MPV`, the first line of `raw`; otherwise the first line of `raw`. Trimmed, cut to 120 chars. Null when `raw` is null or blank.
3. With no status, the first matching rule decides (match case-insensitively on `raw`, so the upper-case Media3 names and the lower-case words both match; then on `reason`): offline (`online == false`) → `net_offline`; Core's post-play give-up text (`gave up after` with `reconnects`, or `no data for`) → `stream_lost`; `ERROR_CODE_BEHIND_LIVE_WINDOW` or `behindlivewindow` → `behind_live_window`; `ERROR_CODE_IO_NETWORK_CONNECTION_TIMEOUT`, `timed out`, `timeout` → `net_timeout`; `unable to resolve host`, `unknownhostexception`, `failed to resolve hostname`, `no address associated` → `net_dns`; `ssl`, `certificate`, `cert_`, `handshake` or reason SSL → `net_ssl`; `connection refused`, `connection reset`, `connectexception`, `ERROR_CODE_IO_NETWORK_CONNECTION_FAILED` or reason NETWORK → `net_refused`; `ERROR_CODE_PARSING_CONTAINER_UNSUPPORTED`, `unrecognizedinputformat`, `none of the available extractors`, `failed to recognize file format` or reason FORMAT → `format_unrecognised`; other `ERROR_CODE_PARSING_*`, `parserexception`, `malformed` → `parse_failed`; `ERROR_CODE_DECODER_*`, `ERROR_CODE_DECODING_*`, `decoder`, `mediacodec` or a decoder/unsupported-video reason → `decoder_failed`; `ERROR_CODE_AUDIO_TRACK_*`, `audiosink`, `audiotrack` or reason AUDIO → `audio_failed`; `ERROR_CODE_DRM_*`, `drm` or reason DRM → `drm_failed`; `Engine.MPV` → `mpv_load_failed`; else `other`. Reason names are Core's `PlayerFailureReason` entries; read the enum, do not guess.
4. `playlist`: status from `httpStatusIn(message)` is kept in `httpStatus`. 429 → `playlist_rate_limited`; 884 → `playlist_m3u_disabled`; offline or DNS/refused/timeout/SSL words (rule 3's lists) → `playlist_unreachable`; `begin_object`, `begin_array`, `expected a list`, `malformed`, `parse`, `json` → `playlist_parse_failed`; else `playlist_download_failed`. `errorName` is the message's first line.
5. `guide`: status kept the same way. Offline or DNS/refused/timeout/SSL words → `guide_unreachable`; `xml`, `parse`, `malformed`, `unexpected` → `guide_parse_failed`; `empty`, `no programmes` → `guide_empty`; else `guide_download_failed`.
6. `withAccount`: status `expired`, `banned`, `disabled`, `wrong_login` replace the code with `account_<status>` and keep `httpStatus`. `active` with `playlist == true`, `maxConnections > 0` and `activeCons >= maxConnections` → `playlist_max_connections`. `active` otherwise, `unreachable`, or a null result leave the code as it was.
7. `Scrubber.text`, in this order: every URL-shaped token (`[a-zA-Z][a-zA-Z0-9+.-]*://\S+`) → `[url]`; `username=`, `password=`, `token=`, `access_token=`, `refresh_token=` query values → `<key>=[removed]`; JSON `"access_token"`/`"refresh_token"` string values → `"[removed]"`; `Bearer <x>` → `Bearer [token]`; JWT-shaped text (`eyJ` + base64url, two dots) → `[token]`; email-shaped tokens → `[email]`; each entry of `secrets` of 4 or more characters, case-insensitive → `[removed]`; then cut to `max`.
8. `Scrubber.host("http://u:p@Panel.Example.com:8080/live/u/p/1.ts")` → `panel.example.com`; anything unparsable → null.

**Constraints:**
- Deviation from AC-13, stated: `unreachable` keeps the original code. The check then learned nothing about the account, and `account_unreachable` would hide a real 403 behind the panel's API being down.
- Secrets shorter than 4 characters are skipped: a one-digit password would blank every digit in a message. URL scrubbing already removes them from stream addresses.
- The research table notes ExoPlayer's "None of the available extractors" message misses Core's FORMAT keywords; that is why rule 3 matches it by text.
- `LiveErrorCodes.FIXED` is written out in Kotlin, not loaded from the JSON at run time; the JSON is the cross-repo check.

**Test intents:**
- `every research table row maps to its code` — table-driven over the research file's main table: each HTTP row as ExoPlayer text (`Response code: N`) gives `http_N`; 403 and 404 also as mpv text (`http: HTTP error 403 Forbidden`); each no-status row (connection failed, TLS, bad container, parse failure, loader crash, decoder failed, decoder init, audio output, state error, behind live window, DRM) gives its code, the loader crash and `IllegalStateException` rows `other` with the class name kept as `errorName`.
- `mpv failure without a status is mpv_load_failed` — `Failed to open http://h/live/u/p/1.ts.` with `Engine.MPV`; and Core's give-up text `no data for 12s; gave up after 5 reconnects` gives `stream_lost`; `ERROR_CODE_IO_NETWORK_CONNECTION_FAILED: java.net.NoRouteToHostException` gives `net_refused`.
- `withAccount replaces only real account findings` — expired/banned/disabled/wrong_login replace, unreachable and active keep, max connections only for playlists.
- `scrubber removes a real Xtream address and every secret kind` — `http://host/live/user/pass/1.ts` loses `user` and `pass` (AC-19); a text holding a URL, an Xtream username and password, an email, a JWT and `refresh_token=abc123def` keeps none of them; output never exceeds `max`.
- `the Kotlin list equals the JSON file` — reads `../tools/kevbox/live-error-codes.json` (unit tests run in `app/`), compares `fixed` to `FIXED`, and checks `http(458)` matches `httpPattern`.

**Behaviour:**
1. `userId` starts from the stored session and follows sign-in, refresh and sign-out the way `email` does, under the same lock.
2. `signedInCall` is the existing private `authorized` made public under the new name, unchanged: one refresh and one retry on a 401; `NoNetwork` reads as `Fetch.Failed`.
3. `recordLiveErrors` and `recordLiveCheckin` post to `rest/v1/rpc/record_live_errors` and `rest/v1/rpc/record_live_checkin` with the bodies in Shared contract, the anon key and the Bearer token, over the existing direct (no proxy) client.

object SendPolicy {
    const val FIRST_WAIT_MS = 60_000L; const val SEND_AT_COUNT = 20; const val BATCH_MAX = 50
    const val MAX_REJECTIONS = 3; const val QUEUE_MAX = 500; const val MERGE_WINDOW_MS = 300_000L

    fun kick()          // an entry was added; re-plan the next send

**Behaviour:**
1. `add` merges into an unsent, not-in-flight entry with the same `code` and `channel` whose `lastAtMs` is within `MERGE_WINDOW_MS` of the new entry's `firstAtMs`: `repeatCount` adds up, `lastAtMs` takes the later value, the other fields keep the first entry's. Otherwise it appends a new entry.
2. Past `QUEUE_MAX` entries, `add` drops the oldest ones until 500 remain (in-flight ones too, as the last resort).
3. Every change rewrites the file atomically (write a temp file, then rename). A missing or unreadable file starts an empty queue. The queue survives a process restart.
4. `settle`: `Sent` removes the ids; `Retry` and `SignedOut` return them to unsent; `Rejected` increments `rejections` and drops entries that reach `MAX_REJECTIONS`.
5. `outcomeOf`: `Ok` with 2xx → `Sent`; `Ok` with 401 → `Retry`; `Ok` with any other 400–499 → `Rejected`; `Ok` with 0 or ≥ 500 → `Retry`; `Failed` → `Retry`; `SignedOut` and `SessionRejected` → `SignedOut`.
6. `backoffMs(1) = 60 s`, `(2) = 5 min`, `(3) = 15 min`, `(≥4) = 30 min`. `nextSendAtMs`: null with nothing unsent; after a failure, `lastFailureAtMs + backoffMs(failures)`; otherwise now when `unsentCount >= SEND_AT_COUNT`, else `oldestUnsentAtMs + FIRST_WAIT_MS`.
7. The sender loop runs on one background dispatcher: wait until `nextSendAtMs` (or a `kick`, a sign-in seen on `userId`), take up to `BATCH_MAX`, send in one `signedInCall { api.recordLiveErrors(...) }`, settle, reset `failures` on `Sent`, increment on `Retry` and on `Rejected` (so a rejected batch waits out the same backoff before its next try, AC-17). On `SignedOut` (including a refused session refresh, where `KevBoxAuth` keeps the stored session and `userId` stays set until the coordinator's next playlist check signs out) the loop pauses `SIGNED_OUT_PAUSE_MS` = 15 min, or until `userId` changes, before it tries again; it never calls the refresh endpoint in a tight loop. With `userId` null it sends nothing and the entries wait (AC-18).
8. `ErrorQueue` lives at `File(context.noBackupFilesDir, "kevbox_live_errors.json")`; Koin binds `ErrorQueue`, `ErrorSender` as singles.

**Constraints:**
- All file access stays on one single-threaded dispatcher (`Dispatchers.IO.limitedParallelism(1)` or equivalent); nothing here runs on the main thread (AC-20).
- In-flight entries are not merge targets: a repeat that lands while its entry is being sent becomes a new entry, and the server merges it (Task 7) so the count is not lost.
- `toJson` writes every Shared contract key, with JSON null rather than a missing key, so the server never has to tell "absent" from "null".
- Timestamps go out as UTC ISO-8601 with `Z` and milliseconds.
- Minor gap transport-5: tag each queued entry with the user id signed in when it was recorded (on the TV only, never sent) and drop, not send, entries whose tag differs from the member now signed in; reset `LiveCheckin`'s last-sent time when `userId` changes.
