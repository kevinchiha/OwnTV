> **For agentic workers:** REQUIRED SUB-SKILL: `subagent-driven-development`. This plan
> states contracts, behaviour and constraints — **it deliberately contains no implementation or
> test bodies**. Read the file you are modifying before writing anything; the plan tells you what

**Goal:** Within 15 minutes of a KevBox Live TV failing with no good play since, Kevin sees it on kevbox.dev and gets one Telegram message with advice, and a second when the customer is watching again.

```kotlin
// SupabaseApi (addition)
suspend fun recordLivePlay(accessToken: String, deviceId: String, appVersion: String, playedAt: String, proxy: Boolean): ApiResponse

// kevbox/usage/PlayNotes.kt
const val PLAY_NOTE_GAP_MS: Long = 60 * 60_000L
const val PLAY_NOTE_TICK_MS: Long = 15 * 60_000L
/** Pure: whether a 30-second play may send a note now. */
fun playNoteDue(lastSentAtMs: Long?, failureSinceLastSent: Boolean, nowMs: Long): Boolean
/** Pure: the TV clock as `yyyy-MM-dd'T'HH:mm:ss.SSSXXX` in [zone], Locale.ROOT. */
fun playedAtText(epochMs: Long, zone: java.time.ZoneId): String
data class PlayNote(val playedAt: String, val proxy: Boolean, val userId: String)
class PlayNotes(
    auth: KevBoxAuth, api: SupabaseApi, deviceId: DeviceId, appVersion: String,
    proxyInUse: suspend () -> Boolean, scope: kotlinx.coroutines.CoroutineScope,
    now: () -> Long, zone: () -> java.time.ZoneId,
) {
    fun start()                 // the 15-minute retry tick; returns at once
    fun onPlayed()              // Task 3: a live channel just reached 30 s
    fun onFailureRecorded()     // Task 3 wires ErrorReporter.addListener to this
    fun onForeground()          // KevBoxCoordinator.onForeground
    internal suspend fun sendPendingNow()   // tests drive it
}
// KevBoxCoordinator (addition): constructor parameter `playNotesOnForeground: () -> Unit = {}`
```

**Behaviour:**
1. `recordLivePlay` posts to `rest/v1/rpc/record_live_play` with exactly the four keys of the Global constraints body, over the existing direct (no proxy) client, never logged.
2. `playNoteDue`: true when nothing was sent in this process, when `failureSinceLastSent`, when `lastSentAtMs > nowMs` (the wall clock moved back), or when `nowMs - lastSentAtMs >= PLAY_NOTE_GAP_MS`.
3. `onPlayed()`: with `userId` null, nothing (no note, nothing pending). Otherwise, when `playNoteDue`, it builds a `PlayNote` (`playedAtText(now(), zone())`, `proxyInUse()` read now, the current user id), makes it the pending note (replacing any older one) and sends it at once. When not due, it does nothing.
4. A send goes through `auth.signedInCall { api.recordLivePlay(...) }`. A 2xx answer clears the pending note, sets `lastSentAtMs = now()` and clears the failure flag. No network, `Fetch.Failed`, a thrown exception, a 0 status or any non-2xx keeps the note pending (AC-5).
5. `onFailureRecorded()` sets the failure flag, so the next 30-second play sends at once whatever the 60-minute limit says (AC-4). The flag lives in memory for this process only.
6. The pending note goes again on the 15-minute tick and on `onForeground()`; never in a tight loop. A pending note whose `userId` differs from the member now signed in is dropped, not sent; signed out, it waits.
7. `KevBoxCoordinator.onForeground()` calls `playNotesOnForeground()` beside `checkinOnForeground()`; Koin passes `get<PlayNotes>()::onForeground`.

**Constraints:**
- At most one note is pending, in memory only. A process restart loses it; the next 30-second play sends at once anyway (nothing sent yet in that process).
- The note carries the device id, app version, time and proxy flag only: no channel, stream address, username or password (AC-6). `PlayNote` has no other field on purpose.
- `playedAtText` uses the explicit pattern: `OffsetDateTime.toString()` drops `:00` seconds, and the server's `live_error_ts` then rejects the text and stores `now()`.
- Sends and the tick run on `scope` with `Dispatchers.IO`; `onPlayed`, `onFailureRecorded` and `onForeground` return at once and are safe on the main thread. Guard shared state with one `Mutex`, like `LiveCheckin`.

**Test intents:**
- `recordLivePlay posts the contract body` — path, Bearer header and exactly the keys `p_device_id`, `p_app_version`, `p_played_at`, `p_proxy` (AC-6).
- `the 60-minute limit and the failure exception` — `playNoteDue`: 59 min after a sent note not due, 60 min due (AC-3); with a failure since, due 5 min after (AC-4); a last-sent time in the future due.
- `a failed send stays pending and a newer note replaces it` — fake API answering no network, then 500, then 200: one call per attempt, the second play's time is the one finally sent, nothing pending after the 200 (AC-5).
- `signed out sends nothing` — `onPlayed` with `userId` null makes no call and leaves nothing pending (AC-5).
- `played-at text keeps zero seconds and the zone` — `playedAtText` of 2026-10-15 22:21:00.000 in Asia/Beirut is `2026-10-15T22:21:00.000+03:00`.

```kotlin
package tv.own.owntv.kevbox.usage

const val PLAY_PROOF_MS: Long = 30_000L

/** One look at Live TV: which channel, whether it plays, whether it failed. */
data class PlayView(val channelKey: String?, val playing: Boolean, val failed: Boolean, val catchup: Boolean)

/** Pure 30-second rule. Feed every change and every tick; true exactly once per uninterrupted run. */
class PlayRun {
    fun onView(view: PlayView, nowMs: Long)
    fun proven(nowMs: Long): Boolean
}

class PlayWatcher(/* notes, reporter, scene, Lazy<LivePreviewEngine>, Lazy<OwnTVPlayer>, scope, now */) {
```

**Behaviour:**
1. A run starts when a live channel (not catch-up) starts playing in the Live TV box or full screen. It ends on an error (`errorInfo` turns non-null), a stop (the engine stops playing), a channel change (`channelKey` changes) or catch-up starting. The next run counts from 0 (AC-2).
2. At 30 s of one run, `notes.onPlayed()` is called once. Nothing more for that run, however long it plays; a new run can prove itself again (Task 2's 60-minute limit decides whether it sends).
3. The watcher waits for `scene.shown` before resolving the engines, like `ErrorWatchers` (a background process builds no player). It ticks at most once a second only while a run is live, so a paused or idle TV wakes nothing.
4. Moving the same channel between the box and full screen keeps counting only if playback did not stop in between; a new engine start is a new run.
5. `start()` calls `reporter.addListener { notes.onFailureRecorded() }` and `notes.start()`. `OwnTVApp.onCreate` starts it with one line, `GlobalContext.get().get<tv.own.owntv.kevbox.usage.PlayWatcher>().start()`, under a `// KevBox:` comment, on the line before the `ErrorWatchers` start, so the first recorded failure already reaches the listener.
