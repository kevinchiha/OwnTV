# KevBox Live 0.1 — design

## Goal

Kevin sets, changes or removes any KevBox member's Xtream playlist from kevbox.dev, and the
member's TV, running the rebranded OwnTV fork "KevBox Live", picks it up by itself within 15
minutes, with no one touching the TV.

## Scope

Two repos, one phase.

**OwnTV fork** (`~/projects/OwnTV`, long-lived branch `kevbox-live`; `main` stays a clean copy
of upstream `ahXN00/OwnTV`):

- Identity: name "KevBox Live", app ID `tv.kevbox.live`, icon, banner, splash, every "OwnTV"
  in shipped text across all locales, signing with the KevBox TV key.
- Sign-in with the member's KevBox email and password; encrypted session kept across restarts;
  an "Account" item in the More menu with Sign out.
- Remote playlist: read the member's rows from Supabase, let a TV whose login has several pick
  one, and create, update in place, hide or bring back the matching local Xtream source.
- Expiry: ask the provider for the line's expiry through Core's `SourceTester` and tell the
  member when it has run out or runs out within 7 days.
- Lock-out: the existing `get_access_verdict()` switch.
- Locked app: hide every way to add, edit, view, copy or restore sources.
- Versions, updates and distribution: four-number versions on top of upstream's, Core's GitHub
  updater pointed at `kevinchiha/OwnTV`, a `release.sh`, the `tv.kevbox.dev/live` short link
  (config file only; applying it is gated).
- Fork hygiene: `// KevBox:` markers, a divergence check script, `UPSTREAM-SYNC.md`, upstream
  GitHub workflows that publish or auto-merge kept from running on the fork.

**kevbox.dev** (`~/projects/kevbox`, work on branch `phase/0.1-kevbox-live` off `main`):

- Migration `0013_member_playlist.sql`: a playlist table with one row per subscription, keyed by
  client number, and a one-row KevBox Live settings table.
- Customer window: a KevBox Live section for that sheet row, with Send, Edit, Remove and Create
  login.
- Settings page: the global Trex server address, which rewrites every matching playlist.
- Audit entries for every KevBox Live action.

## Acceptance criteria

### App identity, versions and distribution

- **AC-1** A release build installs as "KevBox Live" with application ID `tv.kevbox.live`. It
  installs next to KevBox TV (`tv.kevbox`) and stock OwnTV (`tv.own.owntv`) without replacing
  or affecting either.
- **AC-2** The launcher icon, Android TV home-screen banner and splash screen show KevBox Live
  art (the KevBox logo from `kevbox-support/public/Logo/KEVbox.png` with a "LIVE" mark). No
  OwnTV logo art appears anywhere in the app.
- **AC-3** No user-visible string in the merged resources of the release build contains
  "OwnTV", in any shipped locale. The only exceptions are licence and attribution text that
  credits the upstream project, listed by name in `UPSTREAM-SYNC.md`. A script checks this and
  exits non-zero on any other hit.
- **AC-4** Release APKs are signed with `/home/kevin/secrets/kevbox-keys/kevboxtv.jks`.
  `apksigner verify --print-certs` shows SHA-256
  `9A:E0:71:8C:CC:F9:F6:83:90:93:49:31:D3:FE:0E:52:F4:57:EF:B5:81:D5:AC:C1:14:16:F1:51:2D:BB:1D:6F`.
- **AC-5** A release's version name is `A.B.C.K`: `A.B.C` is the upstream version the branch
  is built on and `K` is the KevBox number, 1 to 99, which starts again at 1 on each new
  upstream base. The first release is `5.1.0.1` on upstream `5.1.0`. Its version code is
  `A*1000000 + B*10000 + C*100 + K`: `5.1.0.1` gives 5010001, `5.1.0.2` gives 5010002, `5.2.0.1`
  gives 5020001. A build with no `VERSION_NAME` or `VERSION_CODE` set gets `99.99.99.99` and
  99999999, so a local build installs over any release.
- **AC-6** The in-app updater asks
  `https://api.github.com/repos/kevinchiha/OwnTV/releases/latest` and never `ahXN00/OwnTV`.
  With `5.1.0.1` installed, a latest tag `v5.1.0.2` or `v5.2.0.1` makes it offer the update. A
  latest tag `v5.1.0.1` or `v5.1.0` makes it report up to date.
- **AC-7** `release.sh <version>` builds the `standard` and `x86_64` release APKs with
  `VERSION_NAME` and `VERSION_CODE` set as AC-5 says, verifies their signature against AC-4's
  SHA-256, and creates GitHub release `v<version>` on `kevinchiha/OwnTV` with assets named
  exactly `KevBoxLive.apk` (arm) and `KevBoxLive-x86_64.apk`. It exits non-zero and creates
  nothing when the tree is dirty, when the version is not four numbers with `B`, `C` and `K`
  from 0 to 99 and `K` at least 1, when `A.B.C` differs from the newest upstream `v*` tag
  reachable from `HEAD`, or when the version code is not greater than the latest release's.
- **AC-8** The repo holds an nginx snippet so `https://tv.kevbox.dev/live` answers 302 to
  `https://github.com/kevinchiha/OwnTV/releases/latest/download/KevBoxLive.apk`. Writing the
  snippet is in scope. Installing it on persovps is a gated step.
- **AC-9** On the fork, no GitHub Actions workflow publishes, edits a release, or auto-merges
  a pull request: `release-notes.yml` and `automerge-core-bump.yml` only run when
  `github.repository == 'ahXN00/OwnTV'`.

### Sign-in and session

- **AC-10** On first launch the app shows a sign-in screen (email, password, Sign in) before
  any other screen. The upstream setup wizard's add-source step never appears.
- **AC-11** Correct KevBox credentials sign the member in. A wrong password shows "Wrong email
  or password" and keeps the screen. No network shows "No internet connection" with a Retry
  button. Neither failure crashes the app or clears what was typed.
- **AC-12** The session survives an app restart and a TV reboot without re-entering the
  password. The app stores the refresh token encrypted with an Android Keystore key. It
  refreshes an expired access token without showing the sign-in screen.
- **AC-13** When the server rejects the refresh token (revoked user, deleted user), the app
  returns to the sign-in screen and removes from the device every managed source, visible or
  hidden, their cached channels, the stored playlist pick and the client-number mapping.
- **AC-14** The More menu has an "Account" item whose value is the signed-in email. Its page
  shows the email and a "Sign out" button. Sign out asks "Sign out of KevBox Live?" with Sign
  out and Cancel. Cancel changes nothing. Sign out returns to the sign-in screen and removes
  the same things as AC-13.

### Remote playlist

- **AC-15** The app reads the signed-in member's `member_playlist` rows. When the login has
  exactly one row, the app never asks which playlist to use: it creates one Xtream source with
  that row's name, server URL, username and password, links it to every profile, starts its
  first sync, and stores that row's client number as the TV's pick. Channels appear with no
  member input.
- **AC-16** When the login has two or more rows and the TV has no stored pick, the app shows a
  "Choose your playlist" screen listing the rows by name, sorted by name, with no server,
  username or password shown. The chosen row's client number is stored on the TV and its
  source is created as in AC-15. The other rows create nothing on this TV. Back on this screen
  exits the app without storing a pick, and the next start asks again. While the picked row
  exists, later starts and checks do not ask again, even when rows are added.
- **AC-17** Settings has "Choose playlist" when the login has two or more rows, and does not
  have it otherwise. It lists the rows by name with the TV's current one marked. Choosing
  another row hides the current source as in AC-20, then creates the chosen row's source as in
  AC-15 or brings back its hidden source as in AC-21, and stores the new pick.
- **AC-18** The app checks the rows at sign-in, at app start, when the app returns to the
  foreground, and every 15 minutes while it runs.
- **AC-19** When the picked row's server URL, username, password or name changes, the next
  check updates the existing local source in place. The local source ID stays the same,
  favourites and watch history for that source survive, and a resync starts.
- **AC-20** When the picked row disappears, the next check hides its local source and deletes
  nothing: the source is unlinked from every profile, gets no further sync, and keeps its
  favourites and watch history on the device. With one row left, the app uses it without
  asking. With two or more left, it shows AC-16's screen listing those rows. With no rows left,
  it shows "No playlist assigned yet. Contact admin." in place of the home screen.
- **AC-21** When a row whose client number matches a hidden source becomes the TV's playlist
  again (re-sent from the admin, or chosen in AC-16 or AC-17), the app relinks that same local
  source ID to every profile, applies the row's current name, server URL, username and
  password, and starts a sync. Favourites marked before the source was hidden show again.
  Hidden sources stay on the device until sign-out (AC-13, AC-14).
- **AC-22** A member with no rows at sign-in sees AC-20's no-playlist screen. When a row
  appears later, the next check creates the source (one row) or shows AC-16's screen (two or
  more), and the no-playlist screen gives way to the home screen.
- **AC-23** A check that fails (no network, timeout, HTTP 5xx, malformed response) changes
  nothing on the device. Playback continues, and the next scheduled check tries again.
- **AC-24** A profile created after the source exists gets the TV's current managed source
  linked to it without member input. Hidden sources are not linked to it.
- **AC-25** The app keeps the mapping from client number to local source ID, the hidden flag
  and the stored pick in its own storage, not in Core's database. Core's database schema is
  unchanged.

### Subscription expiry

- **AC-26** The app runs Core's `SourceTester.test` on the TV's current managed source at app
  start and then every 6 hours while the app runs. A check that falls due while a stream plays
  runs when playback stops. With no current source, no check runs. An `Unreachable` or
  `AuthFailed` result shows nothing and keeps the last result.
- **AC-27** When a check returns `Expired`, the app shows a popup "Your subscription has
  expired. Contact admin to renew." with one button, OK. It shows at app start when that
  start's check finds the line expired, and whenever a later check finds it expired. After OK,
  the popup does not show again until the next app start, even when later checks still find the
  line expired.
- **AC-28** When a channel fails to play, the app uses a check result from the last 10 minutes
  or runs a new check. If the result is `Expired`, the player shows "Your subscription has
  expired. Contact admin to renew." in place of the upstream error text. Any other result
  leaves the upstream error text unchanged. After the line is renewed on the Trex panel, the
  first check that returns `Ok` ends both messages: failed channels show the upstream error
  text again, and the next app start shows no expiry popup.
- **AC-29** When a check returns `Ok` with an expiry less than 7 days away, the app shows a
  popup "Your subscription expires in N days. Contact admin to renew." with OK. `N` is the
  days left, rounded up (1 to 7), and N = 1 reads "1 day". The warning shows at most once per
  calendar day on the TV's clock. It never shows when the expiry is null or 7 or more days
  away.

### Lock-out

- **AC-30** The app calls `get_access_verdict()` at app start, on return to the foreground and
  every 5 minutes. `LOCKED` shows a full-screen "Access locked. Contact admin." screen that
  covers every other screen and stops playback.
- **AC-31** `ALLOWED` and `NO_ROW` mean normal use. A failed call or an unauthenticated error
  keeps the last known verdict. A device that has never had a verdict treats it as allowed.
- **AC-32** After Kevin re-enables the member, the next check removes the lock screen without
  a new sign-in.

### Locked app

- **AC-33** No menu, settings page, remote shortcut, deep link or setup step reaches any of
  these: Add source, Manage sources, source edit, add from phone (QR + PIN companion), Local
  sync, Backup and restore (local and remote).
- **AC-34** No settings or source screen, "Choose playlist" included, shows a managed source's
  username or password as text.
- **AC-35** The Telegram group page and QR code and every GitHub link are hidden.
- **AC-36** Everything else works as upstream ships it: live TV, guide, catch-up, movies,
  series, search, favourites, profiles, recordings, multiview and player settings.

### Fork hygiene

- **AC-37** Every changed region in a file that exists upstream carries a `KevBox:` comment
  (`// KevBox:` in Kotlin and Gradle, `<!-- KevBox: -->` in XML, `# KevBox:` in YAML and shell)
  saying what changed and why.
- **AC-38** `tools/kevbox/check-divergence.sh` lists every file that differs from the last
  upstream commit merged into the fork (the merge base with `upstream/main`, not its moving tip)
  and exits non-zero when a changed upstream file has no `KevBox:` marker.
- **AC-39** New fork-only Kotlin lives under `app/src/main/java/tv/own/owntv/kevbox/`. Each
  file starts with a header saying it exists only in the KevBox Live fork.
- **AC-40** `UPSTREAM-SYNC.md` at the repo root covers one-time setup, the merge steps per
  upstream release, a table of every changed upstream file with a command that proves the
  change survived, the hidden-features sweep (new upstream routes to the screens in AC-33), the
  rebrand regeneration steps, and the release steps with AC-5's version rule.
- **AC-41** Core stays unforked: `gradle/libs.versions.toml` still resolves
  `tv.own.owntv:core` and `tv.own.owntv:player-core` from upstream's Maven repository at
  upstream's pinned version.
- **AC-42** The app's existing unit tests pass at the same count as `main` at branch time. New
  unit tests cover the playlist reconcile (one row, several rows with no pick, switching the
  pick, update in place, picked row removed with one, several and no rows left, bringing back a
  hidden source with its favourites, no rows, failed check, new profile), the expiry rules
  (check timing, popup once per app start, expired channel message, warning once a day, `N`
  rounding, `Unreachable` and `AuthFailed` ignored), the verdict states and AC-5's version code.

### Database (kevbox repo)

- **AC-43** Migration `supabase/migrations/0013_member_playlist.sql` creates
  `public.member_playlist` (`id uuid` primary key, `user_id` referencing `auth.users` with
  cascade delete, `client_number text not null`, `name`, `server_url`, `username`, `password`,
  `updated_at timestamptz`, `sent_at timestamptz` set only by Send, unique on `user_id` and
  `client_number`) and
  `public.kevbox_live_settings` (one row, `trex_server_url`). It is idempotent: a second run
  succeeds and changes nothing.
- **AC-44** Row-level security on `member_playlist`: a signed-in member reads only their own
  rows and cannot insert, update or delete. `anon` gets nothing. `kevbox_admin` gets select,
  insert, update and delete. Members and `anon` get nothing on `kevbox_live_settings`.
  Proven on a local Supabase: member A's token returns zero of member B's rows, and `anon`
  gets permission denied.

### Admin (kevbox repo)

- **AC-45** The customer window has a KevBox Live section for that sheet row. It shows the
  `member_playlist` row whose client number matches the sheet row (server, username, and when
  last sent, from `sent_at`, which Edit by hand and server changes leave alone) or "Not on
  KevBox Live". Rows for other client numbers under the same login do not
  show there.
- **AC-46** "Send to KevBox Live" writes the sheet row's Trex username and password, the global
  server address and the row's name to the `member_playlist` row for that login and the sheet
  row's client number, creating or updating it. It is disabled, with the reason shown, when no
  login matches the sheet row's Stremio email (case-insensitive, trimmed), when the sheet row's
  client number, Trex username or Trex password is empty, or when no global server address is
  set.
- **AC-47** When the sheet marks the row expired or cancelled, Send stays enabled and the
  section shows "The sheet marks this subscription expired." or "The sheet marks this
  subscription cancelled." Neither mark removes or changes any `member_playlist` row.
- **AC-48** The section shows "Sheet and TV differ" when the sheet row's Trex username or
  password differs from the stored row for its client number.
- **AC-49** "Edit by hand" appears when a row exists for the sheet row's client number and
  saves a typed server, username and password to that row.
- **AC-50** "Remove from KevBox Live" deletes the row for the sheet row's client number after
  a confirm step. The login's rows for other client numbers stay.
- **AC-51** "Create login" appears when the sheet row has a Stremio email and no matching
  login. It creates the Supabase login with password `kevbox<clientNumber>` without enrolling
  in AIOStreams and without needing a debrid token. When a login already exists, it says so and
  changes nothing.
- **AC-52** The Settings page has a "Trex server address" field. Saving a new value updates
  `server_url` on every `member_playlist` row that held the previous value, in one transaction,
  and reports how many rows changed.
- **AC-53** Each Send, Edit, Remove, Create login and server change writes a `kevbox_audit`
  row with the admin's email and one of `live.send`, `live.edit`, `live.remove`,
  `live.create_login`, `live.server_change`.
- **AC-54** New vitest tests cover AC-46 to AC-53. The existing kevbox suite has no new
  failures.

### End to end

- **AC-55** On the `kevbox_tv` emulator against a local or test Supabase, a test member signs
  in. A playlist sent from the admin appears without a prompt. An edited password shows on the
  device after the next check with the source ID unchanged. A favourite is marked, the
  playlist removed, and AC-20's no-playlist screen shows. Re-sending the same client number
  brings back the same source ID with the favourite. Sending a second client number to the same
  login keeps the TV on its pick; signing out and in again shows AC-16's screen.

## Non-goals

- **M3U and MAC (Stalker) playlists.** Kevin's customers use Xtream (Trex); the table can add
  a type column later.
- **Several playlists on one TV at once.** A TV shows only its picked playlist; the others
  stay off it, so a member cannot take another TV's line and trip the stream cap.
- **A server record of which TV uses which playlist.** The pick lives on the TV; the admin
  shows the playlist per sheet row, not per device.
- **A device limit.** Kevin decided against it; Trex's own stream cap limits sharing.
- **Instant push.** A 15-minute check is enough for a playlist changed a few times a year.
- **Encrypting stored Xtream passwords.** The app must decrypt them to play, and Xtream puts
  them in every stream URL anyway.
- **Masking credentials in the player info overlay and error log.** Upstream Core already
  masks them there.
- **Replacing TiviMate.** A possible later payoff, not this phase.
- **Forking OwnTV_Core.** Doubles every upstream merge; all changes stay in the app layer.
- **Running the migration on production, deploying kevbox.dev, installing the nginx snippet,
  pushing, or publishing a release.** Each is a gated step for Kevin, outside the unattended run.
- **Telemetry and watch-history sync.** KevBox TV has them; KevBox Live does not need them yet.

## Decisions

- Backend: the existing hosted KevBox Supabase project. Rejected: self-hosted Supabase on
  persovps. Why: reuses logins, admin, backups and monitoring, and adds no servers to run.
- Users: existing KevBox members with their KevBox TV email and password. Rejected: separate
  IPTV-only accounts. Why: one login per person, and the lock-out and member list already exist.
- Locked app. Rejected: members adding their own sources, or editing the pushed one. Why:
  Kevin controls playlists, and members never see Xtream credentials.
- How the TV gets its playlist: it reads Supabase directly under row-level security. Rejected:
  an API on kevbox.dev (makes TVs depend on persovps), and realtime push (more moving parts).
- Login source in the admin: pulled from the sheet when Kevin clicks Send. Rejected: typed
  only (two copies drift), and fully automatic from the sheet (a cell typo reaches a TV).
- Missing logins: a "Create login" action without AIOStreams. Rejected: creating logins by hand
  in the Supabase dashboard. Why: 6 of the 9 customers with no login have no debrid token, and
  today's login creation needs one.
- Lock-out yes, device limit no. If a device limit ever returns, keep signing with the KevBox TV
  key: `ANDROID_ID` depends on the signing key, so two keys make the two apps on one TV evict
  each other under `claim_device()`'s newest-device-wins rule.
- Distribution: GitHub releases on `kevinchiha/OwnTV` with a `tv.kevbox.dev/live` short link.
  Rejected: self-hosting like KevBox TV. Why: Core's updater already reads GitHub releases
  (`CoreBuildInfo.releaseRepo` is set by the host app), so no updater code is needed.
- Constant asset names (`KevBoxLive.apk`, `KevBoxLive-x86_64.apk`). Rejected: versioned names.
  Why: GitHub's `releases/latest/download/<name>` link only works with a fixed name, and Core's
  updater picks assets by `.apk` and the `x86_64` marker, not by name.
- Supabase access with plain OkHttp REST calls (GoTrue sign-in and refresh, PostgREST reads, one
  RPC). Rejected: the supabase-kt library. Why: OkHttp is already a dependency, and four calls
  don't justify a new library tree.
- Approach: B, the full agreed design. Rejected: A, a lean fork (English-only rebrand, server
  address per send, manual releases); C, a personal proxy Xtream address per member with no app
  fork (persovps in every channel load, uneven player redirect handling, no rebrand).
- Long-lived branch name `kevbox-live` at Kevin's word. Rejected: `kevbox`.
- Rebrand strings: overrides in the app regenerated by a script from Core's strings at the
  pinned Core version (about 80 default-locale strings mention OwnTV, across 158 locale files).
  Rejected: hand-copied overrides. Why: a script reruns cleanly at every Core bump.
- OwnTV's minimum of Android 8 stays. Kevin confirmed no member TV runs anything older.
- Size: kept as one phase at the user's word (55 criteria)
- Households: one `member_playlist` row per sheet row (subscription), unique per login and
  client number, named after the sheet row. Rejected: extra logins with made-up emails (more to
  manage), and one shared playlist per login (every TV on one Trex line hits the stream cap).
  Why: 20 emails cover several active subscriptions, and 19 households had 2 or 3 lines under
  one login on 2026-10-13 (e.g. clients 285, 286 and 388, in different countries).
- One playlist per TV: a TV whose login has several asks once, stores the pick on the TV, shows
  only that one, and switches through Settings > "Choose playlist". If the picked one is
  removed, the TV asks again among those left, or shows the no-playlist screen when none
  remain. A login with one playlist is never asked. Rejected: every playlist on every TV, and
  storing the pick on the server. Why: a member could take another TV's line and trip the
  stream cap, and a pick on the TV needs no server change.
- Player info overlay and error log: no extra criterion and no sync-doc check. Rejected: a
  checked divergence. Why: upstream Core already masks credentials there.
- Versions: upstream version plus a fourth KevBox number (`5.1.0.1`). Rejected: an own line
  from 0.1.0. Why: shows the upstream base at a glance, and Core's updater compares numeric
  segments one by one, so four numbers work.
- Sign out: an "Account" item in the More menu with the signed-in email and Sign out.
  Rejected: inside About or a Settings card.
- Removal hides the source (unlinked from every profile, no resync) and keeps its favourites.
  Re-sending the same client number brings it back with them. Hidden sources stay until
  sign-out. Rejected: deleting the source with its favourites. Why: Kevin wants favourites kept.
- Send to a customer the sheet marks expired or cancelled: allowed, with a warning in the
  window; nothing is removed automatically. Rejected: blocking Send. Why: the sheet can lag a
  renewal.
- Expiry: the TV tells the member when the line has expired (popup at app start and on each
  check that finds it, gone after OK until the next start; the expired message in place of a
  channel error) and warns once a day in the last 7 days. Rejected: no early warning.
- Expiry source: the provider, asked through Core's `SourceTester`, so renewing on the Trex
  panel clears the message at the next check. Rejected: the sheet's Trex expiry date. Why: the
  sheet lags renewals.
- Member-facing text says "admin", never "Kevin", on every screen (expired, expiring, locked,
  no playlist). Rejected: naming Kevin. Why: Kevin's call.
- No contact-line setting: the wording is fixed in the app. Rejected: a kevbox.dev Settings
  field the TV fetches. Why: Kevin's call.
- auto-resolved: expiry checks run at app start and every 6 hours, wait while a stream plays,
  and a failed channel reuses a result from the last 10 minutes; rejected checking with each
  15-minute playlist check; why: each check takes a Trex connection slot for a moment, and an
  expiry date only moves on renewal.
- auto-resolved: `Unreachable` and `AuthFailed` results show nothing and keep the last result;
  rejected treating a refused login as expired; why: an outage or a wrong password would tell a
  paying member to renew.
- auto-resolved: early-warning `N` is days left rounded up, "1 day" for one, and "once a day"
  means once per calendar day on the TV's clock; rejected rounding down; why: rounding down
  shows "0 days" on the last day.
- auto-resolved: a login with one row stores that row as the TV's pick, and a row added later
  does not prompt a TV that has a pick; rejected asking again whenever a row is added; why: a
  TV already in use keeps working, and the new TV is asked at sign-in.
- auto-resolved: switching in "Choose playlist" hides the old source the same way a removal
  does; rejected deleting it; why: the same favourites rule applies.
- auto-resolved: "Choose playlist" appears only when the login has two or more rows; rejected a
  one-item list; why: there is nothing to choose.
- auto-resolved: Back on the "Choose your playlist" screen exits the app without a pick;
  rejected defaulting to the first row; why: a default could take another TV's line.
- auto-resolved: the TV maps client number to local source ID; rejected mapping by row ID;
  why: removing and re-sending creates a new row ID, and the client number is what brings the
  hidden source back.
- auto-resolved: version code `A*1000000 + B*10000 + C*100 + K` with `B`, `C`, `K` up to 99
  and `K` from 1, and local builds fall back to `99.99.99.99` and 99999999; rejected upstream's
  three-number formula; why: it leaves no room for `K`, while this one always grows and keeps a
  local build installable over a release, as upstream intends.
- auto-resolved: `release.sh` checks `A.B.C` against the newest upstream `v*` tag reachable
  from `HEAD`; rejected trusting the typed number; why: a typo there would misstate the
  upstream base on every TV.
- auto-resolved: Sign out asks for confirmation; rejected signing out on one press; why: sign-out
  drops hidden sources and their favourites.
- auto-resolved: "Edit by hand" works only on an existing row; rejected creating a row from
  Edit; why: Send gives the row its name and client number from the sheet.
- auto-resolved: Send is disabled when the sheet row has no client number; rejected sending
