### Notes

1. **Full screen tried both engines.** The full-screen 403 failed on the Live engine and then on
   mpv (the screen shows `MPV`); both had the same code and channel within 5 minutes, so the
   server merged them into one row with `repeat_count 2`, which keeps the first entry's `engine
   exo`. The crash event's breadcrumbs show both entries. This is the designed merge (AC-15), not
   a fault. To keep the preview and full-screen rows apart, the full-screen check used a channel
   the preview check had not touched; the server merges same-channel failures within 5 minutes
   whatever the surface.
2. **No "isn't responding" box appeared.** The plan says to choose "Close app" in Android's box.
   On this emulator the system closed the app itself 0.4 s after declaring the ANR
   (`am_kill: … user request after error`) and never drew the box; polling the screen every 2 s
   from 20:32:57 found no "responding" text, and the next look showed the launcher. Android still
   recorded the exit as `REASON_ANR` (6), which is what the SDK reads, and the event arrived. I did
   not use `force-stop`. The box itself, and "Close app", get their check on the TCL after the
   build (the plan's "After the build", step 6).
3. **Account check spacing.** `AccountCheck` asks the panel at most once per 10 minutes per source
   (`MIN_GAP_MS`), in memory. Check 4 ran after the crash of check 5 had restarted the process, so
   it got a fresh check and saw `Expired`. Within one process, a status change on the panel shows
   up in rows only after that gap.
4. **Stray app on the emulator.** While I learned the sign-in screen's keys, a Back press left
   KevBox Live and the next key opened KevBox TV debug (`tv.kevbox.debug`) from the launcher, which
   started its own hero preview. I pressed Home and force-stopped `tv.kevbox.debug`. KevBox Live
   was not force-stopped at any point.
5. **Sign-in keys.** OK on a field opens the keyboard; type with `input text`; Enter commits and
   returns to the field; ▼ moves to the next field and then to Sign in. Taps do nothing here.

## Fixes made in this task

- `KevBoxCoordinator.onForeground()` now also calls the usage check-in's own foreground check
  (`LiveCheckin.onForeground`), passed in by Koin as `checkinOnForeground`. Before, nothing called
  it, so after a TV slept past the 6-hour timer an app open sent no check-in. Covered by the new
  `KevBoxCoordinatorTest` case "each foreground hands the usage check-in its own foreground check,
  and start does not".
- The open item "nothing calls `ErrorReporter.start()`" was stale: `OwnTVApp` starts
  `ErrorWatchers`, whose `start()` starts the reporter (Task 5). Checks 2 to 4 show the reporter
  running.
- `UPSTREAM-SYNC.md`: the OwnTVShell row's proof `grep -n 'it.kind ==
  tv.own.owntv.features.home.ContinueKind.LIVE'` matched nothing since commit `3ea93d09` moved that
  filter into `LiveShortcuts.continueChannel`; it now greps the new line. Every proof command in
  the table exits 0.
