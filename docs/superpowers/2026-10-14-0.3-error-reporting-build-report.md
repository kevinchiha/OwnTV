## Rolled-up minors

- Task 7, `lane-2-progress.md`: The commit adds lane-2-progress.md at the repo root, which is not on the Files list. It looks like the lane's progress ledger, not product code, but if it is not meant to reach main, the owner should drop it before the lanes merge.
- Task 7, `scripts/prove-live-error.sh`: Checks d and e run `grant kevbox_admin to postgres` and `grant authenticated to postgres` and never revoke them. The header says the script cleans up what it creates, but it only removes the users and rows. The harm is small because the stack is thrown away, but either revoke both grants in cleanup() or say in the header that they stay.
- Task 7, `supabase/migrations/0015_live_error.sql`: On the local stack, prune_live_errors(integer) has proacl {postgres, service_role, kevbox_admin}: service_role keeps EXECUTE through Supabase's default function privileges. AC-29 says only kevbox_admin may run it. The grant block matches the brief word for word and service_role already has full access, so this is a note for the plan owner, not a fault of the implementation. If AC-29 is meant literally, add `revoke all on function public.prune_live_errors(int) from service_role` in a later plan change.
- Task 8, `packages/core/src/liveErrors.ts`: getLiveErrorSummary groups hours with date_trunc('hour', last_at) on a timestamptz. That cuts at hour marks in the session's time zone, not UTC. Under a time zone with a half-hour offset (Asia/Kolkata, for example), every bucket would start at :30 UTC. Supabase sessions run in UTC, so production is fine today. Writing date_trunc('hour', last_at at time zone 'UTC') at time zone 'UTC', or setting the time zone explicitly, would make the result the same everywhere. The test's `% 3_600_000 === 0` check only holds under whole-hour offsets.
- Task 9, `src/lib/__tests__/live-error-labels.test.ts`: The research-status loop only checks that each title matches `^<status> · \S`. The range fallback produces that same shape, so the test would still pass if an entry such as 458 or 884 were dropped from HTTP_STATUS_LABELS. A stronger check is `HTTP_STATUS_LABELS[status]` defined for each listed status (777 excluded) and the title equal to `${status} · ${HTTP_STATUS_LABELS[status].label}`. Right now every listed status does have its verbatim label, which I checked against the brief by hand, so this is a weak test, not a bug.
- Task 9, `src/lib/live-error-labels.ts`: HTTP_CODE (`^http_(\d+)$`) accepts more than the contract's httpPattern (`^http_[1-9][0-9]{2}$`). It accepts http_0999 and http_1234, for example, and the title then shows the number from Number() rather than the code as sent. The server should never store such codes, so nothing breaks today. Building the regex from codes.httpPattern, or reusing that text, would keep the two in step.
- Task 11, `src/components/kevbox-live-errors.tsx`: fetchLiveErrors writes its own same-origin fetch and its own JSON error-message parsing. The Api client in src/lib/admin/api.ts already does both for the other /api/members routes. Adding a liveErrors method there would have meant editing a file outside this task's Files list, so the copy is understandable. It is still a second copy of the same error handling. The owner could fold it into Api after the lanes merge.
- Task 11, `src/components/kevbox-live-errors.tsx`: The Interfaces block lists CAUSE_TEXT as something this task consumes, but the component never uses it. None of the behaviour lines asks for a cause column, so nothing is missing. The Interfaces entry is just unused here.
- Task 11, `lane-2-progress.md`: The commit also edits lane-2-progress.md, which is not on the Files list. It is the lane's progress ledger and earlier tasks updated it the same way, so this note is for the record only. The entry repeats the 5.1.0.10 wording, which is the brief's own stated deviation from AC-38.
- Task 12, `src/components/admin/live-errors-view.tsx`: In a code's row list, clicking the row itself navigates through a TableRow onClick, which has no tabIndex, role or key handler, so a keyboard user can't trigger it. The 'Client n' links inside the row still reach the same place, so nothing becomes unreachable. Only the whole-row click is mouse-only.
- Task 12, `src/components/admin/live-errors-view.tsx`: The 'TVs per app version' count button shows the total number of TVs across all versions (the sum of v.tvs). The brief only says 'four counts', so this reading is reasonable, but nothing in the plan pins it down. If Kevin expected the number of versions, the button will show a different figure.
