### Part 1: findings

- **W-1 important** · kevbox `src/components/kevbox-live/customers-tab.tsx:202-206` with `kevbox-live-page.tsx:57-67` · AC-35. On Overview, the four TV-count buttons ("Watched today…", "…7 days", "…30 days", "Recording on…") should open Customers at All TVs. The first time they are clicked, Customers mounts and the `[section]` effect calls scrollIntoView at once, while Drifting, Gone quiet and Everyone still show one-line "Loading…". When those tables load above All TVs they push it down, and the effect never runs again. If the loading page is too short to scroll, the view stays at the top, and browsers do no scroll anchoring at offset 0. Result: the operator lands at the top of Customers, not at All TVs. A second click works. Drifting is unaffected because it is the first section. The test (customers-tab.test.tsx) only checks that scrollIntoView ran once. Fix: scroll once the 30d load (and the section's own data) has settled.
- **W-2 minor** · kevbox `src/app/api/members/[userId]/live-diary/route.ts:10,42` + `packages/core/src/liveUsage.ts:401,412` · AC-31. The route accepts any run of digits for `page`, and core pastes `offset ${(page - 1) * PAGE_SIZE}` into the SQL text. A page of about 2e17 or more overflows bigint (or prints as "5e+21"/"Infinity"), so the operator gets a 500 instead of an empty page or a 400. No injection: the value is always a JS number. Fix together with known minor 12.
- **W-3 minor** · kevbox `src/components/admin/live-errors-view.tsx:30,68-69`; `src/lib/live-usage-format.ts:42`; `src/lib/customer-deeplink.ts:20-27` · AC-28, AC-40. The deep link is built in three places: customerDeepLinkHref(n, tab); usageCustomerHref, which appends "&tab=usage" by hand; and a local customerHref with its own WindowTab type. Same strings today; customer-deeplink.ts still calls itself the "single source of truth". Fix: both callers use customerDeepLinkHref(n, "live"/"usage").
- **W-4 minor** · kevbox, parallel-lane duplicates git could not see. `type Period` in customers-tab.tsx:18 as well as channels-tab.tsx:15; `type Section` in kevbox-live-page.tsx:23 and customers-tab.tsx:19; identical dayLabel/monthLabel in customer-usage-tab.tsx:45-47 and overview-tab.tsx:43-45; customer-usage-tab.tsx:23 declares a `Loaded<T>` with a different, keyed shape under the same name the other three files use; the text "Could not load KevBox Live usage: <err>" names two different failures (All TVs at live-errors-view.tsx:373, the window summary at customer-detail-dialog.tsx:174).
- **W-5 minor** · kevbox `packages/core/src/liveUsage.ts:227` and `liveUsageFleet.ts:76` · AC-30, AC-36. The hour-grid pre-filter `s.started_at < <Beirut midnight of $3> + interval '1 day'` adds 24 h in a UTC session. Beirut's 2026-10-24 is 25 h long, so when it closes a range, stretches starting in the repeated 23:00 hour drop out of the grids. Fix: `((($3::date + 1)::timestamp) at time zone 'Asia/Beirut')`.
