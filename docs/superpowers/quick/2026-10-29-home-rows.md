# Home screen rows: Recent channels and Favorites

## Goal
KevBox Home (and any Android TV launcher) shows two KevBox Live rows, "Recent channels" and "Favorites", whose cards open that channel full screen in one press.

## Scope
New fork-only code under `app/src/main/java/tv/own/owntv/kevbox/home/`, one start line in `OwnTVApp.kt`, one receiver in `AndroidManifest.xml`, two keys hidden in `LiveOnlySettings`, Core pins in `CoreContractTest`, a section and table rows in `UPSTREAM-SYNC.md`.

**Gate:** `GRADLE_USER_HOME=/home/kevin/.gradle ./gradlew testStandardDebugUnitTest lintStandardDebug && bash tools/kevbox/test-release-checks.sh && bash tools/kevbox/check-divergence.sh`
(commit first: check-divergence reads committed work only.)

## Acceptance criteria
- **AC-1** The system TV provider holds a `TYPE_PREVIEW` channel from `tv.kevbox.live` named "Recent channels" with one program per live channel in the active profile's watch history (the same history as the app's Recently watched), newest first by weight, at most 15. Removing a channel from Recently watched (Hold OK, or More › Clear history) takes its card off within 5 s.
- **AC-2** A second `TYPE_PREVIEW` channel, "Favorites", holds the active profile's favourite live channels, at most 15, in the order the app's Favorites category shows them (the guide's Order setting: Provider, A–Z, Catch-up first or Favourites first). Starring or un-starring a channel in Live TV or the guide changes the row within 5 s.
- **AC-3** On a TV with neither channel, "Recent channels" is created before "Favorites" (lower `_id`). Both keep their `_id` across app restarts (ids kept in prefs). A channel deleted outside the app is made again on the next sync. Every other channel of the package (OwnTV's own "Recent live", duplicates) is deleted on each sync, found by internal provider id.
- **AC-4** Every program has: `title` = the channel name (the member's rename if any); `short_description` = the title of the programme on now from the stored guide, or nothing when the guide has none; `poster_art_uri` = Core's fitted 16:9 logo (`LiveLogoPosterArt`, a `content://` file) once it exists, the raw logo URL before that, none without a logo; `poster_art_aspect_ratio` = 16:9; no `duration_millis` or `last_playback_position_millis`; `internal_provider_id` = a key stable per channel; `intent_uri` = an `ACTION_VIEW` intent for `owntv://play/live?sourceId=…&remoteId=…&name=…` with its package set to the app's own (no app chooser).
- **AC-5** Starting a card's intent (`am start` of its `intent_uri`) with the app closed, or open on another screen, opens KevBox Live full screen on that channel. A channel not in the active profile's playlists opens the app on its normal start screen with nothing playing.
- **AC-6** Within 5 s of a sign-out both channels hold zero programs (the channels stay). Signing in fills them again.
- **AC-7** A profile switch shows the new active profile's lists.
- **AC-8** The rows also refresh: when MainActivity stops (Home, another app), at boot (`BOOT_COMPLETED`), on `ACTION_INITIALIZE_PROGRAMS`, and from a periodic background job every 30 minutes that runs with the app closed, so the programme-on-now lines stay current.
- **AC-9** OwnTV's own TV home publishing stays off: the first sync sets Core's `androidTvHomeEnabled` to false (Core then publishes nothing), and Settings › App no longer shows "Android TV home" or "Refresh now", in the list or in settings search.
- **AC-10** A sync writes nothing for a program whose values have not changed, and deletes only programs no longer wanted.
- **AC-11** Every upstream-file edit carries a `KevBox:` comment and has a row with a proof command in `UPSTREAM-SYNC.md`; `UPSTREAM-SYNC.md` gains a "Home screen rows" section; `CoreContractTest` pins each Core member the new code reads; `check-divergence.sh` passes.
- **AC-12** On the `kevbox_tv` emulator, with KevBox Home installed there, both rows show cards with logos and on-now lines, and OK on a Recent card plays that channel.

## Non-goals
- No change to KevBox Home. Kevin decides there how two KevBox Live rows appear.
- No `requestChannelBrowsable` call and no reliance on `browsable`: Google TV never sets it for third-party channels and its "add channel" screen can't show from the background.
- No Watch Next row (movies and episodes are gone from KevBox Live).
- No on/off switch for the rows (Kevin, 2026-10-29: hide the old switch, rows always on).
- Nothing on Kevin's test box (192.168.68.69) without his yes; never the TCL (.71).

## Decisions
- Own channels over Core's existing "Recent live", because Core's row has no boot or sign-out refresh, one channel per profile, no on-now line, and an implicit `owntv://` link that can open a chooser; Core is a prebuilt library, so none of that can be fixed in place.
- Favorites in the guide's order over newest-first: Kevin's pick, 2026-10-29.
- Sync driven by Room flows (watch history, favourites), the KevBox session email, the active profile and the guide Order setting, debounced 1 s, over hand-placed calls in each view model: every path that changes history or favourites (Hold OK remove, Clear history, guide star, Live star) is covered without touching upstream files.
- WorkManager for the periodic and boot jobs over KevBox TV's JobScheduler: the fork already runs `SilentUpdateWorker` the same way, through Core's `KoinWorkerFactory`, which hands unknown workers to WorkManager's default factory.
- Core's `LiveLogoPosterArt` and its exported `LiveLogoArtProvider` for logos over raw URLs: KevBox Home centre-crops art to the card, which cuts a square logo; the fitted file pads the logo onto a 16:9 canvas.
- Core's `LauncherDeepLink.Live` and the shell's existing handler for opening a channel over a new link format: the shell already resolves it against the active profile and plays it full screen; a signed-out TV holds the link until sign-in.
- On-now lines read the stored guide the way `GuideNow` does, one batched `nowProgrammesFor` call for both rows, never `nowNext` (no provider calls).

## Tasks

### Task 1: What the rows hold
**Delivers:** AC-1, AC-2, AC-4, AC-10
**Files:** `app/src/main/java/tv/own/owntv/kevbox/home/HomeRows.kt`, `app/src/test/java/tv/own/owntv/kevbox/home/HomeRowsTest.kt`
**Interfaces:**
- `enum class HomeRow(val providerId: String) { RECENT("kevbox-live:recent"), FAVORITES("kevbox-live:favorites") }`, RECENT first.
- `data class HomeCard(val key: String, val title: String, val description: String?, val artUri: String?, val intentUri: String, val weight: Int)`; `key` is `"ch:<sourceId>:<remoteId or name>"`.
- `object HomeRows` with pure functions: `recent(history: List<ChannelEntity>, ..., link: (ChannelEntity) -> String)`, `favorites(channels: List<ChannelEntity>, sort: GuideSort, ..., link: (ChannelEntity) -> String)`, each returning `List<HomeCard>` (≤ 15, weight highest first). `link` builds the card's `intentUri`; Task 2 passes the real one (Core's `LauncherDeepLink.Live(...).toUri()` in an `ACTION_VIEW` intent with the app's package, `Intent.toUri(URI_INTENT_SCHEME)`), tests pass a fake, since `Uri` is a stub in unit tests.
- `data class ExistingProgram(val rowIds: List<Long>, val title: String?, val description: String?, val artUri: String?, val intentUri: String?, val weight: Int)`, in `HomeRows.kt`: one stored card, every row id the provider holds for its key (first is kept, the rest are duplicates).
- `diff(wanted: List<HomeCard>, existing: Map<String, ExistingProgram>): HomeDiff`, with `data class HomeDiff(val insert: List<HomeCard>, val update: List<Pair<Long, HomeCard>>, val delete: List<Long>)` (update pairs a kept row id with its new card; delete holds row ids).
**Does:**
- Drops channels hidden by the profile's Live customizations and channels outside the profile's live sources; applies renames to titles.
- Favorites ordering copies `EpgViewModel`'s `guideOrder` comparator for each `GuideSort` value.
- `diff` updates only cards whose stored values differ, deletes keys no longer wanted and duplicate rows of one key.
**Tests:** Recent keeps history order and caps at 15; Favorites follows A–Z and Provider order; `diff` of identical inputs is empty and a removed channel yields one delete.
**Verify:** `GRADLE_USER_HOME=/home/kevin/.gradle ./gradlew testStandardDebugUnitTest --tests 'tv.own.owntv.kevbox.home.*'`

### Task 2: Writing the rows and keeping them current
**Delivers:** AC-3, AC-5, AC-6, AC-7, AC-9 (Core switch-off), AC-8 (leaving the app)
**Files:** `kevbox/home/HomeChannels.kt` (provider reads and writes), `kevbox/home/HomeRowsSync.kt`, `kevbox/di/KevBoxModule.kt`, `OwnTVApp.kt` (one start line, `KevBox:` comment)
**Interfaces:** `class HomeRowsSync { fun start(); suspend fun syncNow() }`; `syncNow()` is what Task 3's worker calls.
**Does:**
- `HomeChannels` creates or reuses the two channels (prefs file `kevbox_home_rows`), deletes other channels of the package, reads existing programs without a selection clause (filtering by channel id in memory, as KevBox TV does) into `Map<String, ExistingProgram>` keyed by internal provider id, applies a `HomeDiff`.
- Core builds `LiveLogoPosterArt` inline and binds none in Koin, so `KevBoxModule` adds `single { LiveLogoPosterArt(androidContext(), get()) }` (Core's `OkHttpClient`).
- `HomeRowsSync.start()` collects the flows in Decisions, debounced 1 s; signed out or no profile → both rows emptied; registers activity callbacks so a `MainActivity` stop (not a configuration change) syncs at once.
- Each sync first turns Core's `androidTvHomeEnabled` off and clears Core's rows for every profile when it was on.
- Asks `LiveLogoPosterArt` to prepare missing fitted logos and syncs again when they are written.
- Does nothing on a TV without the leanback feature.
**Tests:** a sign-out empties both rows; the Core switch is turned off once (fake reads, no provider).
**Verify:** `GRADLE_USER_HOME=/home/kevin/.gradle ./gradlew testStandardDebugUnitTest --tests 'tv.own.owntv.kevbox.home.*'`
