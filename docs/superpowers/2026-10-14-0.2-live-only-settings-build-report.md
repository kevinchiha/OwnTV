1. **Step 1:** lane-1 = Task 1, one-lane `phase-build-lanes` run.

   - lane-4 = Task 6

   - lane-6 = Task 8

3. **Step 3:** Task 12 (UPSTREAM-SYNC rows, full gate) with a plain sub-agent on the integration worktree, then Task 13 (install on Kevin's TV) by the orchestrator, ending on Kevin's check.

No file is written by two lanes. Step 2's longest lane is 4 tasks of 10, so at best about 2.5× faster than one at a time. Gradle runs one build at a time across lanes (`/home/kevin/projects/.worktrees-OwnTV/gradle-locked.sh`, a flock wrapper outside the repo): the PC has 31 GB, and each Gradle + Kotlin daemon pair takes up to 12 GB, with another session's daemons already running. So the real speed-up is smaller: agents read and write in parallel, but builds wait in line.
