- Task 1 · `app/src/main/java/tv/own/owntv/kevbox/network/LocalRelay.kt` (AC-17): acceptLoop returns on any IOException from accept(), not only when stop() closed the listener. A one-off accept failure (for example 'Too many open files') ends the accept thread for good, while `server` stays set and the socket stays bound. start() then keeps returning the same port, and new player connections wait in the listen backlog until the player gives up. Nothing recovers it until stop()/start() or an app restart. Fix: return only when `listening.isClosed` or `server !== listening`; otherwise continue, ideally after a short pause.
- Task 1 · `app/src/main/java/tv/own/owntv/kevbox/network/LocalRelay.kt` (AC-15): closeAllLocked() closes every connection while holding the shared lock. Connection.close() closes in reverse attach order, so the SSLSocket is closed before its underlying plain socket. On some TLS stacks, closing an SSLSocket tries to send close_notify, or waits for a write lock that a copy thread blocked in write() is holding. That can stall start()/stop() (and every other relay operation) while the lock is held. Closing the plain socket first, or closing outside the lock, would avoid this.
- Task 1 · `app/src/main/java/tv/own/owntv/kevbox/network/LocalRelay.kt` (AC-15): The host-name check calls okhttp3.internal.tls.OkHostnameVerifier, which is OkHttp's internal package (OkHttp 5.5.0 here). The brief names it, and it works today, but an OkHttp upgrade can move or change it without notice. A pin in CoreContractTest, or a comment marking the dependency, would make an upgrade fail loudly instead of breaking the relay quietly.

## Raised outside the per-task loop

- **important (security), Task 4, `kevbox/network/ManagedProxy.kt`** (automatic commit security review, 16:4x, while lane-1 ran): when the relay cannot bind any port (fail closed, AC-16), Core's proxy is still saved as `127.0.0.1:<kept or 61129>` with the playlist's proxy login, so another app on the TV that binds that port receives the Basic login and every stream URL (which carries the customer's IPTV login).
