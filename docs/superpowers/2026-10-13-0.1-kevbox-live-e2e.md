  carries the production link along, and no command against the copy should be able to reach it.
  `supabase start --workdir <copy>` came up with API on `127.0.0.1:55321` and DB on `55322`.
  tawle's stack on 54321–54323 kept running untouched.

  (id `b7a78b83-…`). `grant kevbox_admin to postgres` ran first.
- **Device.** `run.sh --emulator-only` booted `kevbox_tv` as `emulator-5554`, `qemu.hwcodec.avcdec`
  empty (software h264), clock corrected by 12380 s.
- **App.** `./gradlew assembleX86_64Debug -Pkevbox.supabaseUrl=http://10.0.2.2:55321

  `app/build/outputs/apk/x86_64/debug/app-x86_64-debug.apk` and `am start -n
  tv.kevbox.live/tv.own.owntv.MainActivity`.
- **Admin writes.** Every send, edit and delete ran as `set role kevbox_admin` through `psql` against
  the local DB, using the same statements as `kevbox:src/server/admin/live.ts` (`upsertLiveRow`,
  the delete). A "next check" was forced with `input keyevent HOME` then `am start`, which runs
  the foreground check (AC-18, AC-30).
- **Evidence.** Screen lines are `screen.sh emulator-5554` output. Database lines come from a copy of
  `databases/owntv.db` with its `-wal` and `-shm` files (`adb exec-out run-as tv.kevbox.live cat`),

## Findings for the whole-branch review

1. **Black screen after the lock lifts.** To reproduce: play a channel full screen, lock the
   member, wait for the lock screen, then set `active = true` and bring the app back (HOME + `am
   start`). The lock goes away, but the app comes back on the full-screen player with nothing
   playing: a black screen with no text nodes and no new stream request. Back returns to Live TV.
   With no lock involved, the same HOME + `am start` cycle keeps the stream playing, so the gate
   causes this: it stops playback when it leaves Open, as designed (AC-30), and the restored
   player route never restarts. AC-32 holds (no new sign-in), but the member is left on a black
   screen until they press Back. Not fixed in this task.
2. **The brief's admin insert cannot run as `kevbox_admin`.** `insert … select id … from
   auth.users` fails with `ERROR: permission denied for schema auth`. The real admin code
   (`kevbox:src/server/admin/live.ts`) looks the member up in `public.kevbox_auth_users`, which
   migration 0006 grants to `kevbox_admin`. This run used that view.
3. **Fake panel keep-alive.** The first version of `fake_xtream.py` answered with HTTP/1.0 and
   closed each connection. OkHttp reused a pooled connection and failed with `unexpected end of
   stream`, so one sync (source 2, 16:08:16) fetched categories but no channels (`· 0 channels`).
   The panel now speaks HTTP/1.1 keep-alive, as real panels do, and the next sync loaded all 6
   channels. This was a bug in the test server, not in the app.
4. **Side effect of the walk.** Key presses during the Settings walk switched the test install of
   KevBox Live to the light theme. Only `tv.kevbox.live` changed; KevBox TV was not touched.
